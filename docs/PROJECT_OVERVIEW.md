# Basic Incremental — Project Overview

The project as it is built right now (version 0.5.5): one entry per system, screen and data area, with what it does today, where it lives and which rule in `docs/DESIGN.md` it implements ("DESIGN §n"; UI rules are in `docs/UI_RULES.md`, art rules in `docs/ASSET_RULES.md`). It describes only what exists in the code. Plans, targets and open questions live in DESIGN.md.

**This file is rewritten in place.** Every PR that changes `src/` updates the entries it touches (add, change or delete them) so the file always equals the code. No history and no "removed" notes: a deleted feature simply drops out. Exception: a tiny direct-in-Code job with no behaviour change (typo, comment, one-line fix) puts the line `no overview change` in its PR description.

## Project shape

Windows desktop game, Electron + TypeScript, built with electron-vite; tests are vitest (`tests/`, `helpers.ts` has `plainContent`, `freshState`, `newGame`). Numbers use `break_eternity.js` (`Decimal`). Save format version 26 (`CURRENT_SAVE_VERSION` in `src/game/save.ts`; format 25 sent every dungeon back to floor 1 of Normal, "replay Normal first", and added the training levels, DESIGN §6; format 26 added the state of the balance update, see State below: each production job's main card became the worker of its first tree or mine and each dungeon's boss kills the stage kills of its Normal last floor).

| Folder         | What it is                                                                                                                                                                         |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/game`     | Pure game logic (no DOM, Electron or Node). The only door for the UI is `src/game/index.ts`.                                                                                       |
| `src/data`     | Content JSON (`content/*.json`), zod schemas and `loadContent`. The only door is `src/data/index.ts`.                                                                              |
| `src/main`     | Electron main process: window, IPC, save files, auto-update, logs.                                                                                                                 |
| `src/preload`  | The bridge (`window.api`) the renderer may call.                                                                                                                                   |
| `src/renderer` | The UI: shell, pages, stage effects, widgets, themes, sound and art.                                                                                                               |
| `tests`        | vitest suites for logic, data, view models and art helpers.                                                                                                                        |
| `scripts`      | Checks (`check-*.mjs`), the balance sim (`sim/`), art bake (`art/`) and screenshot scripts (`shoot-*.mjs`, `probe-app.mjs`).                                                       |
| `design`       | Exploration pages, option mockups, screenshots, pixel drafts (`design/pixel`), local references (never committed).                                                                 |
| `.claude`      | Optional helper agents (`ui`, `pixel-art`, `mechanics`), the `pixel-art` skill (with `references/style/`, the user's Keep + Learn style picks) and the shared permission settings. |
| `.github`      | `ci.yml` (lint, test, build on PRs and main) and `release.yml` (tag `vX.Y.Z` builds and publishes the installer).                                                                  |

**Contract between logic and UI.** The renderer imports game code only from `src/game/index.ts` and `src/data/index.ts`, never from files inside them; `src/game` never imports UI, Electron or Node. ESLint enforces both (`eslint.config.mjs`). The renderer has no game rules: adapters (`pages/*Adapter.ts`, `pages/*Model.ts`) turn state into view models. Dev cheats are the separate `game/dev` entry, not exported from `index.ts`; `npm run build` fails when a release bundle contains them (`scripts/check-release-bundle.mjs`).

**Dev profiles.** Dev builds share one save folder (`%APPDATA%\basic-incremental-dev`). Two dev apps at once autosave over each other, so give each its own: `BI_PROFILE=<name>` (or `--bi-profile=<name>`) uses `%APPDATA%\basic-incremental-dev-<name>`, `BI_USER_DATA_DIR=<folder>` uses that folder as is. Names are letters, digits, `-` and `_`; packaged builds ignore both (`src/main/devPaths.ts`, DESIGN §2).

**Commands.** `npm run dev`, `npm run lint` (eslint, prettier, `check-design`, `check-workflow`), `npm run typecheck`, `npm test`, `npm run build`, `npm run sim -- --hours 40` (balance sim, DESIGN §14; it plays the shipped portals, the Legacy Gate closed, and prints pulls per hour; `--seeds 20` for balance PRs, `--profile active|idle|both`, `--strict`), `npx tsx scripts/sim/timeline.ts` (one run row by row), `npx tsx scripts/sim/rarity.ts` (rarity gaps).

## Data (`src/data`)

`schemas.ts` holds the zod schemas (stats, cosmetic slots/tokens); `index.ts` exports `loadContent` and `Content` (including `allPortals` with disabled portals, `portals` with enabled ones, `allDungeons` and `dungeons`, which differ only when a dungeon's data says `enabled: false` (none does today; `loadContent({ unreleased: true })` would open it), `legacySkinById`). Content files in `content/`: `account`, `achievements`, `cardRules`, `cards`, `coins`, `combat`, `cosmeticRules`, `cosmetics`, `dungeons`, `enhancements`, `items`, `mines`, `portals`, `prestige`, `production`, `progression`, `rarities`, `resources`, `sets`, `trees`, `training`, `trials`, `upgrades`, `weaponSkins`, `wearRules`. Every number and piece of content lives there, not in logic (DESIGN §2, §3). `coins.json` is the coin ladder Money is shown in (DESIGN §3 Coins): `settings/coins.ts` in the renderer (`coinAmount`, `moneyText`, `amountText`) turns an amount of Money into a count and a coin for the header chip (`createShell`'s `coins` option, tinted by `data-coin` in `shell.css`), the buy buttons, the shelf, training, card costs, the dungeon drops panel and the welcome-back summary; other resources keep the Settings number style.

## Electron (`src/main`, `src/preload`)

`main/index.ts` (window, IPC), `saves.ts` and `saveStore.ts` (save files, autosave, final save before close), `updater.ts` (auto-update on launch, DESIGN §2), `fileLogger.ts` and `logTail.ts` (logs and the Report-an-issue text), `devPaths.ts` (dev profiles), `devMode.ts` (whether dev cheats are on: unpackaged builds only). `preload/api.ts` defines `window.api`.

### Stage effects (`stage/`)

`arena.ts` (the boss fight), `director.ts` (reports to moments; boss attacks come from `TickReport.bossAttacks`; each hit carries the main card's hit interval), `theme/attackSpeed.ts` (the attack animation plays over 40% of that interval, clamped to 200–900 ms, so a dagger swings fast and a hammer slowly; DESIGN §6), `bossHitModel.ts` (edge pulse, chunk spans, "You fall in"), `numbers.ts` (floating numbers), `fly.ts` (coins to the header), `motion.ts` (one shared animation loop), `harvestParty.ts` (one Production band's fan, gauge, supports chips and lunges), `tierUp.ts`, `toast.ts`, `reveal.ts` (summon), `welcome.ts` (welcome-back card fan), `math.ts`. Reduced motion is respected everywhere (UI_RULES §2).

### Widgets (`ui/`)

`card.ts` and `cardFace.ts` (full-art card layout; bottom plate built by `pages/cardFaceModel.ts`), `loadoutFan.ts` (main card with supports fanned behind and pop-out; used by each Production band and in the dungeon party), `weaponPanel.ts` (XP ring, level badge, star pips, tier plate, price chips and the tier-up button; model `pages/weaponModel.ts`), `buy.ts` (×1/×10/×100/Max controls), `shelf.ts` (upgrade shelf), `hpStack.ts`, `cosmeticSwatch.ts`, `skins.ts` (equipped UI-skin style), `resourceIcons.ts`, `pixelNumbers.ts`, `skillArt.ts`, and `pixelScale.ts` + `pixelFit.ts` + `pixelScale.css` (whole device-pixel scales, `--dpr`, `fitCard()`; DESIGN §12 / ASSET_RULES §5).

### Theme and sound

`theme/`: `apply.ts` (tokens and recipes), `frames.css` (the pixel-frame panel and button recipe, step from `--dpr`; Pixelify Sans display font and Atkinson Hyperlegible body font from `@fontsource`, DESIGN §8, UI_RULES "Shell look"), `registry.ts` (implemented cosmetic ids), `recipes.css`, `rank.css`, `base.css`, `effects.ts`/`effects.css` (hit animations, art-owned). `sound/`: synthesized Web Audio effects (`engine.ts`), the sound registry as data, settings and the header mute (DESIGN §13).

### Art (`art/`, rules in `docs/ASSET_RULES.md`)

Vector sources (`vector/`: items, frame, gems, bosses, tiles; the item art keeps the old seven-step rarity ladder as its own `ArtRarity`) and drawing code (`items.ts`, `frame.ts`, `gems.ts`, `bosses.ts`, `evolutions.ts`, `fx.ts`, `fxGeometry.ts`, `kit.ts`, `cosmetics.ts`, `cosmeticIds.ts`), plus the pixel pipeline in `art/pixel/`: `raster.ts` (raster treatment), `bake.ts` and `manifest.ts` (baked sprites, run by `scripts/art/bake-pixels.mjs`), `sprites.ts` and `sprites/` (baked PNGs), `hand/` (hand-made PNGs: coins, tiles, items, medals, evolutions `evo-*`, shop art `shop-*`, legacy skins `skin-scythe-01..12`, `skin-staff-03`, six `skin-bow-*` with palette-cycling strips), `live.ts` (live canvas motion), per-weapon motion strips for every T5, T6 and Heirloom item (flames, orbiting ghosts, falling petals and so on; `scripts/art/make-shine.py`) and `animate.ts` (palette cycling: a sprite with a strip `<name>-anim.png` of pre-rendered frames, played at 110 ms a frame, still under reduced motion; DESIGN §12). Card borders, finishes and corner flourishes are generated (`cosmetics.gen.ts`, `scripts/art/cosmetics-gen.mjs`).

## Scripts and CI

- `scripts/check-design.mjs`: every rule in `docs/DESIGN.md` and `docs/UI_RULES.md` has a status tag, no amendment-style sections.
- `scripts/check-workflow.mjs`: a PR that changes `src/` must change this file or say `no overview change` in its description; nothing but a README may remain in `docs/plans/` on main (`CLAUDE.md`, Workflow).
- `scripts/check-cards.mjs`, `check-dungeons.mjs`, `check-pixel-scale.mjs`, `check-release-bundle.mjs`, `a11y-*.mjs`: content, pixel-scale, bundle and accessibility checks.
- `scripts/sim/`: balance sim playing the real game logic against the pacing targets (DESIGN §14), with target ranges, the spread and worst seed of each milestone, the band check (median within 25% of the target, worst seed within 2×), an idle profile beside the active one (a check-in every 30 min, 8 h offline a day on the game's own offline progress), the median DPS per quarter hour, the median Card Portal and Wardrobe Gate pulls per hour, milestones for the first Hard and Nightmare clears and Dungeons 4 to 6, a sim player that pushes floors and climbs the tiers and the endless depths when nothing else is waiting, and per run the time to its first 5 run milestones (Money earned since the Ascension, 10K to 100M) with the Ascension guard that names runs slower than the run before (DESIGN §6); `rarity.ts` prints the rarity gaps (base, fresh, free stars, top tier) and fails when a higher rarity does not beat a lower one (DESIGN §5).
- `scripts/shoot-*.mjs`, `probe-app.mjs`, `probe-attack-speed.mjs` (measures the attack animation for a dagger and a hammer lead), `demo-progression.mjs`: screenshots and probes of the running app.
- `scripts/art/picker.mjs`: writes the interactive picker page (labelled pictures, Keep, Learn, Copy list) for every choice between pictures (`CLAUDE.md`, Workflow).
- `.github/workflows/ci.yml` runs `npm run lint`, `npm test` and `npm run build` on every PR and on pushes to main; `release.yml` publishes a GitHub Release when a `vX.Y.Z` tag is pushed (`RELEASING.md`).
