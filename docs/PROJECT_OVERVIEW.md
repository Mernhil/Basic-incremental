# Basic Incremental — Project Overview

The project as it is built right now (version 0.7.2): one entry per system, screen and data area, with what it does today, where it lives and which rule in `docs/DESIGN.md` it implements ("DESIGN §n"; UI rules are in `docs/UI_RULES.md`, art rules in `docs/ASSET_RULES.md`). It describes only what exists in the code. Plans, targets and open questions live in DESIGN.md.

**This file is rewritten in place.** Every PR that changes `src/` updates the entries it touches (add, change or delete them) so the file always equals the code. No history and no "removed" notes: a deleted feature simply drops out. Exception: a tiny direct-in-Code job with no behaviour change (typo, comment, one-line fix) puts the line `no overview change` in its PR description.

## Project shape

Windows desktop game, Electron + TypeScript, built with electron-vite; tests are vitest (`tests/`, `helpers.ts` has `plainContent`, `freshState`, `newGame`). Numbers use `break_eternity.js` (`Decimal`). Save format version 36 (format 36 replaced the upgrade shelf with milestone picks: `upgrades.owned` became `upgrades.picks`, and every shelf upgrade owned paid its Money back, DESIGN §4; `CURRENT_SAVE_VERSION` in `src/game/save.ts`; format 25 sent every dungeon back to floor 1 of Normal, "replay Normal first", and added the training levels, DESIGN §6; format 26 added the state of the balance update, see State below: each production job's main card became the worker of its first tree or mine and each dungeon's boss kills the stage kills of its Normal last floor; format 27 added the state of the table update, see State below: the crystals held became scrolls, 300 to one, and the crystals were dropped; each dungeon's auto-challenge switch is on where it was pushing, the empty support slots of the fighting loadout were filled with the best owned fighting cards the cost cap allows (`migrationTeam.ts`, a snapshot of the card list), a player standing on a dungeon with no floor beaten was moved to the last dungeon with one, and a knockout the save was parked in was cleared, DESIGN §6; format 28 is the cosmetics cleanup: the removed cosmetics (the attack slot's items, every finish, tick and number item, the Prism Pointer) are unequipped and dropped from the owned lists and the three removed bow skins from the legacy skins, each owned copy refunded as a fifth of a Glamour Scroll, DESIGN §8; format 29 is readable numbers: Money, gems held, lifetime harvests, lifetime Money, depth progress and account XP move to the new scale through the maps in `V29_SCALE` (`migrations.ts`), the same maps the level prices, the tier-up gems and the mastery thresholds were moved with; the run's own gems are moved so the Starlight an Ascension would give stays what it was (the lifetime harvest grows to hold them where needed); the fight in progress starts fresh, DESIGN §14 Readable numbers; format 30 is the Heirloom Gate: a card at the old Heirloom tier goes back to Mythic/Void ★6 and its Heirloom becomes its own card, DESIGN §5 Saves keep their Heirlooms; format 32 is the Dragon batch: the 22 Heirlooms become 11, a removed Heirloom owned goes to the kept one of its type (`v31ToV32`, `V32_HEIRLOOM_MERGE`), DESIGN §5); format 35 is four equal loadout slots in a formation: the fighting loadout and every dungeon preset, a main card and three supports, become `{ slots }` (back left, front left, front right, back right), and the step flags the state (`arrangeFormation`) so `readSave` puts each team's two highest-health cards in the front row (`arrangeFormation`, `arrangeSavedFormations` in `cards.ts`; `v34ToV35`, DESIGN §5 Loadouts); format 34 is quests: `quests` (quest id -> `{ doneAt, claimed }`) starts empty (`MIGRATIONS[33]`), and the first tick after reading an older save marks every quest it already meets as done and waiting to be claimed, never claimed (DESIGN §10 Quests); format 33 is card skins: the skin chosen per weapon type (`weaponSkins`) is copied onto every owned card of that type and dropped, so each card looks as before (`v32ToV33`, `V33_CARDS_BY_KIND`, a snapshot of the card list; DESIGN §8). `tests/fixtures/saves/` holds real saves of formats 23, 25 and 26 (0.6.0) a made-up format 27 save that owns removed cosmetics and a format 28 late-game save (30 h of the sim on 0.7.5, seed 3), which the migration tests load.

**Contract between logic and UI.** The renderer imports game code only from `src/game/index.ts` and `src/data/index.ts`, never from files inside them; `src/game` never imports UI, Electron or Node. ESLint enforces both (`eslint.config.mjs`). The renderer has no game rules: adapters (`pages/*Adapter.ts`, `pages/*Model.ts`) turn state into view models. Dev cheats are the separate `game/dev` entry, not exported from `index.ts`; `npm run build` fails when a release bundle contains them (`scripts/check-release-bundle.mjs`).

**Dev profiles.** Dev builds share one save folder (`%APPDATA%\basic-incremental-dev`). Two dev apps at once autosave over each other, so give each its own: `BI_PROFILE=<name>` (or `--bi-profile=<name>`) uses `%APPDATA%\basic-incremental-dev-<name>`, `BI_USER_DATA_DIR=<folder>` uses that folder as is. Names are letters, digits, `-` and `_`; packaged builds ignore both (`src/main/devPaths.ts`, DESIGN §2).

**Hidden test window.** `BI_HIDDEN_WINDOW=1` opens the window far off-screen, without focus and without a taskbar button, for automated test and screenshot runs that must not appear on the user's screen; the page still renders, so screenshots over `--remote-debugging-port` work. Unpackaged runs only (`src/main/devMode.ts` `hiddenTestWindow`, used in `src/main/index.ts`).

**Local dev build.** A private build for testing, made by scripts kept only on the developer's PC in the git-ignored `local-dev/` (not in the repo, not in CI or a release). The repo holds only the gate: `BI_DEV_BUILD=1` at build time is baked in as `__BI_DEV_BUILD__` (`electron.vite.config.ts`, which then builds into `out-dev/`; `src/main/buildFlag.ts`): dev cheats on although packaged (`devCheatsEnabled(app, env, devBuild)`: unpackaged on, dev build on, public release off), updater off, window title "... Dev", own save folder `%APPDATA%asic-incremental-devbuild`. DESIGN §2.

**Commands.** `npm run dev`, `npm run lint` (eslint, prettier, `check-design`, `check-workflow`), `npm run typecheck`, `npm test`, `npm run build`, `npm run sim -- --hours 40` (balance sim, DESIGN §14; it plays the shipped portals, not the Legacy Gate, which is looks only, and prints pulls per hour; `--seeds 20` for balance PRs, `--profile active|idle|both`, `--step 5` for the first 2 h and `--late-step 15` after, `--strict`), `npx tsx scripts/sim/timeline.ts` (one run row by row), `npx tsx scripts/sim/breakdown.ts` (one run: where the fighting damage comes from, by modifier source, signature and crits, and the crystal multiplier), `npx tsx scripts/sim/rarity.ts` (rarity gaps), `npx tsx scripts/sim/ranges.ts --hours 40 --seeds 1` (the range of every number family at set hours, the content ladder of every dungeon and tier, and an end-of-content team of four Mythic and Void Heirlooms; DESIGN §14 Readable numbers). The sim's reports print numbers in the short format.
