# Basic Incremental — Game Design

The source of truth for the game's design. It holds one version of every rule: the current one. Anything not covered here is an open question for the user.

## How this document works

Every rule starts with a status tag:

| Tag          | Meaning                                                                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `[Built]`    | Decided by the user and in the game as written.                                                                                         |
| `[Differs]`  | Decided by the user. The game has it but works differently: the text is the target, and the rule says what the game does today.         |
| `[To build]` | Decided by the user, not in the game yet.                                                                                               |
| `[Default]`  | Filled in by Claude; the user has not decided it. `[Default · in game]` when it is built. Every default is listed under Open questions. |
| `[Proposed]` | Suggested in a chat and waiting for the user's answer. Not built. Every proposal is listed under Open questions.                        |

Rules for keeping this file clean (they also bind every Claude session, in claude.ai and in Claude Code):

1. **One version of each rule.** This file holds only the current design. A change rewrites the rule where it lives. Never add amendment, update, addendum or "defaults" sections, and never leave an old version next to the new one.
2. **Every rule has a tag.** `npm run lint` runs `scripts/check-design.mjs`, which fails when a rule has no tag or an amendment-style section appears, so CI blocks it.
3. **Only the user decides.** When something is missing, Claude asks. If work cannot wait, Claude writes its choice where the rule belongs, tagged `[Default]`, and lists it under Open questions; it stays a default until the user confirms it. Claude never changes a decision of the user's on its own: a tuning that needs to break one is a question, not an edit.
4. **Decisions reach the repo first.** A decision made in a claude.ai chat is written as edits to this file. The prompt for Claude Code starts with those edits, and Claude Code commits them before any code. A chat decision that is not in this file is not a decision yet.
5. **Tags move with the code.** A PR that builds or changes a rule updates its tag in the same PR (`[To build]` or `[Differs]` becomes `[Built]`). A rule the game no longer matches is never left `[Built]`.
6. **Rules, not tuning.** Exact tuning numbers live in `src/data/content`, and the rule names the file. This file keeps the rules, the targets and the numbers the user decided. Tuning stories go in the PR description.
7. **Changelog.** A changed or dropped rule gets one dated line at the end: what changed and who decided it.
8. **Say where things stand.** Asked whether something exists, Claude answers with its tag (built, differs, to build, default, proposed), never just "it already exists".

The layered version this file replaced (sections 11 and 12 as amendments) is in git history at commit `ac33acd`.

## 1. The game

- [Built] A Windows desktop incremental about collectible cards: two production jobs (logging and mining) and auto-fought dungeons, with a gacha for cards and cosmetics. Customization is the main feature. Made mainly for the user, maybe for others.
- [Built] **Brave Frontier is the main reference** for style, screen order, upgrades, the evolution feel and the gacha, adapted to a desktop app: no characters as cards, no turn-based combat, no energy or stamina timers.
- [Built] **Three loops** (§3): dungeons pay Money and scrolls, production pays materials, and both are spent on cards and cosmetics.

## 2. Distribution, saves and tools

- [Built] A Windows `.exe` built with Electron and TypeScript; unsigned is fine. Pushing a version tag (`vX.Y.Z`) builds it in GitHub Actions and publishes a GitHub Release. The app checks for updates on launch.
- [Built] **Saves** are JSON on disk with autosave and export / import. They are versioned: every format change bumps the version and adds a migration.
- [Built] **Offline progress** follows the same rules as online play and is capped at about 8 hours.
- [Built] **Dev tools** (user, 2026-11-10). Dev builds take `BI_PROFILE` / `--bi-profile` or `BI_USER_DATA_DIR` so parallel dev apps never autosave over each other. Dev cheats are pure functions in the separate `game/dev` entry, allowed only in unpackaged builds (the main process reports it), and `npm run build` fails if a release bundle contains them. A small dev cheats panel, present in dev builds only, calls those `game/dev` functions (Ctrl+Shift+D or its "Dev" button: resources, dungeon clears, a card's rank, account XP, cosmetics, time); it never ships in a release build.
- [Built] **Report an issue** opens a pre-filled GitHub issue with the app version, a save summary, OS and Electron versions and the last log lines, kept under about 7,500 characters. The player can edit it before submitting.

## 3. Economy: the three loops

- [Built] **Money comes only from dungeons**: a wage per second while fighting the first dungeon's boss (not while knocked out) and a purse on every kill in every dungeon (`dungeons.json`). A new game starts with 30 Money (§14 Readable numbers, `[Default]` of the rescale, Claude, 2026-11-12; it was 100). Its display name lives only in `resources.json`.
- [Built] **Money buys** tree and mine levels, the upgrade shelf (§4) and weapon tier-ups (§5). The three damage lines it used to buy are gone (§5).
- [Built] Every Money price is a curve `base × growth^n` in the data files, read through `cost.multiplier` and `cost.growth`.
- [Default · in game] **Price growth cuts never stop a price growing** (Claude, 2026-11-11, balance run). A `cost.growth` cut (Wide Skies, Fresh Start, Wide Groves, Deep Roots) takes its percent off the part of the growth above 1, so −10% turns ×1.2 into ×1.18, and all the cuts together take at most half of it (`MAX_GROWTH_CUT` in `production.ts`). Before, the cuts added up to 15% on mines and 36% on trees, took ×1.13 down to the floor of 1, and levels stopped costing more: Money ran away after about 58 hours.
- [Built] **Coins** (user, 2026-11-10: "upgrading coins instead of mathematical numbers"). Money is shown in the biggest coin it fills instead of a long or scientific number: 950 is "950 Copper", 12,400,000 is "12.4 Gold". The header chip shows the count, names the coin and tints its coin to match; prices, purses and offline gains in Money read the same way. Display only: the game still counts Money as one number, and nothing is exchanged. The coins are data (`coins.json`); past the last coin its count keeps growing in the one short number format (UI_RULES §2 Readable numbers).
- [Built] The coin ladder (`coins.json`; Claude's proposal, confirmed by the user on 2026-11-10): Copper, Silver, Gold, Diamond, Star, Moon, Sun, Crown, each worth 1,000 of the one before (Silver from 1,000 Money, Gold from a million, Diamond from a billion). Counts show three digits, rounded down. The user's example steps (silver at 1,000, gold at 10,000, diamond at a million) were uneven; even steps of 1,000 keep every count between 1 and 999. The coin sprites are the Coin_Gems spinning coins (user, 2026-11-11), recoloured per coin by script: Copper from the red coin, Silver from the silver coin, Gold from the gold coin, Diamond to Crown from those. The Money rate under the header chip stays a plain number per second.
- [Built] **Ladders** (user, 2026-11-10; between dungeons changed 2026-11-11; the rate of Dungeons 4 to 6 changed 2026-11-12). Inside a dungeon the ladder grows at one steady rate, ending on the boss as `dungeons.json` has it: every floor is ×1.101 the HP and attack of the one above in Dungeons 1 to 3 (§14 Readable numbers, `[Default]` of the rescale, Claude, 2026-11-12; it was ×1.12), and Dungeons 4 to 6 use a gentler rate (user, 2026-11-12: "yes gentler floor rate is fine"), because their bosses are only ×3 to ×4 apart over 40 to 60 floors and at ×1.12 most of their floors sat below the boss before them. The gentler rate is a `[Default]` of the table update's balance pass 3 (2026-11-12): ×1.0169 a floor in all three (×1.02 before the readable-numbers rescale; `dungeons.json` `floorGrowth`; a dungeon without one uses `combat.json` `floors.hpGrowth`, 1.101), so the first floor of Dungeons 4, 5 and 6 is worth 2.2, 1.9 and 1.04 times the boss before it and their mini-bosses take 23 to 28 s (§6 Floors pace). An enemy's purse is its share of the boss's HP, so purses follow the same rate, with 2% more for every floor deeper (§6 Deeper pays more; `combat.json` `floors`). A dungeon's floor rate carries on through its difficulty tiers and its endless depths (§6). Between dungeons the pacing targets (§14) win over a steady rate (user, 2026-11-11: "keep the targets"): a steady rate cannot meet them, because power grows fast in the first hours (three tiers by hour 4) and slowly after (one tier between hours 4 and 25), while the targets put 60 floors in the first 12 hours and 150 in the next 24. So each boss is set from the targets (balance run, 2026-11-11; the table update's balance runs moved them again, 2026-11-11 and twice on 2026-11-12; the readable-numbers rescale of 2026-11-12, §14, put them on the new scale as `[Default]`s): Root Warden 5,030 HP, Cinder Lich 112,000, Glacier Colossus 4.51 million, Storm Roc 17 million, Dawn Hierophant 68.9 million and The Unmade King 195 million (they were 98,000, 5.6 million, 648 million, 3.02 billion, 15.3 billion and 51.2 billion), purses and Core chances in step with the HP (Core chances unchanged, so Cores per second of fighting stay as they were; a boss purse is now about half its HP in Money early and a quarter late, where it was a tenth), and attack set against the HP so a team that just matches a boss takes about 15 to 25 s over it (§6 Fight pace): Root Warden 20 every 3 s, the others 469, 33,800, 94,400, 378,000 and 1.27 million every 2.5 or 2 s (they were 58.9, 1,920, 225,000, 684,000, 3.16 million and 12.2 million; `dungeons.json`). Balance pass 3 raised each boss's HP 1.35 to 1.7 times and cut its attack to 0.6 to 0.95 of what it was, more in Dungeons 4 to 6, whose fights were the shortest. Bosses climb ×22 and ×40 a dungeon early and ×2.8 to ×4.1 late. Tier-ups should cost about the same amount of play time at each step (§5); tier-up Money is 5,300, 13,000, 260,000, 1 million and 4 million, plus 7.2 million for the Heirloom step while it is still in the game (`[Default]` of the rescale; it was 20k, 60k, 2M, 10M, 50M, 100M; §5 Tier-up costs) and not measured as equal play time per step.
- [Built] **Production pays materials only**: the six gems. Gems, Cores, Frost Sigils, Glimmer Dust and Facet Shards pay for card upgrades, cosmetic upgrades and tree unlocks. Nothing in production pays Money.
- [Built] **Scrolls are the premium tier.** The Summon Scroll pays for the Card Portal and the Focus Portal and the Glamour Scroll for the Wardrobe Gate. Only the portals spend them, and Ascension keeps them. One scroll pays one pull (a 10-pull costs ten). There are no crystals any more.
- [Built] **Scrolls replace the crystal wage** (user, 2026-11-10 gameplay brainstorm: summoning "more like AFK"; picked "Summon scrolls"). Nothing ticks in per second: scrolls come in lumps and are saved up, Summon Scrolls for the Card Portal and the Focus Portal, Glamour Scrolls for the Wardrobe Gate. They come from the first win of a floor (`scrolls.json` `floorFirstWin`: by floor kind, times the difficulty), a dungeon's first clear (`dungeons.json` `firstClear`), the stage chests (§6 Stage stars), achievements and account levels (§10, §11), and a daily reward claimed in the Summon view once a local day (`scrolls.json` `daily`, the day kept in `summon.dailyClaimedDay`). Only the first dungeon still pays a Money wage while fighting, so the first levels can be bought before the first kill (§6).
- [Default · in game] Scroll details: the crystals a save held became scrolls at the pull price (300 crystals for one scroll, rounded down; save format 27 drops the crystals), and a new game starts with one Summon Scroll, its one free pull (`resources.json`). Every crystal price and reward was divided the same way, so a scroll amount may be a fraction of one (a shard-shop bundle of 3,000 crystals is 10 scrolls; an achievement of 150 is half a scroll): amounts add up, and a pull needs a whole scroll. The "first win of a Challenge floor" pays when the best floor of a difficulty rises (`payFloorFirstWin`, called where the floor is cleared); its amounts are placeholders for the balance run. Scrolls are kept through Ascension, as crystals were.
- [Default · in game] **The field cache** (Claude, 2026-11-11, table update balance run). A steady source, so a player who farms keeps pulling: every 10 minutes of play time while a dungeon (or the Glimmer Trial) is fought, online or offline within the cap, pays a lump of 1.25 Summon and 0.625 Glamour Scrolls, ×1.25 on Hard and ×1.5 on Nightmare and the endless depths (Harder modes pay more, §6; the trial counts as Normal), and the shelf's Crystal Lure and the Starlight shop's Constellation Crystals multiply it (`scrolls.json` `fieldCache`). It is paid on whole multiples of the period on the play-time clock, so any split of time pays the same, and it follows time, not kills, so pulls never grow with kill speed (§6 Normal enemies). Without it the sim pulled 17 times in the first hour and none an hour after that, and the missing copies held back every tier-up.
- [Default · in game] What each source pays (`scrolls.json`, `dungeons.json`; Claude, table update; the first wins and the daily reward cut in the balance run, 2026-11-11): the first win of a floor pays 0.1 Summon and 0.05 Glamour Scrolls on a wave floor, 0.5 and 0.25 on a mini-boss floor, 1.5 and 0.75 on a boss floor (they were 0.25, 1 and 3), times 1 on Normal, 2 on Hard, 4 on Nightmare and 2 on an endless depth (the shelf's Crystal Lure and the Starlight shop's Constellation Crystals multiply it); the daily reward is 3 Summon and 1.5 Glamour Scrolls (it was 5 and 2.5); the field cache above pays the rest; first clears pay 1 / 0.5, 3 / 2 and 5 / 3 scrolls in the first three dungeons (the old 300 / 150, 900 / 600 and 1,500 / 900 crystals divided by 300). The old crystal wage (0.5, 0.6 and 0.7 a second, the user's "middle wage" of 2026-11-10) is gone with the crystals. With these numbers the sim's Card Portal pulls about 15 times in the first hour and 15 to 25 an hour after (§14).
- [Built] **Heirloom Scrolls** (user, 2026-11-12, asked whether the Heirloom Gate should be reachable early with ordinary Summon Scrolls: "nah end game weapons"; the scroll itself is Claude's proposal of the same day, not objected to). A fourth scroll, the Heirloom Scroll, pays for the Heirloom Gate (§7) and nothing else. It is earned only late in the game: Nightmare bosses, the deepest floors and Ascension. It is kept through Ascension like the other scrolls, and Summon and Glamour Scrolls never pay for the Heirloom Gate.
- [Default · in game] **Where Heirloom Scrolls come from** (Claude, 2026-11-12; rough amounts, tuned with the sim after the number rescale; `heirlooms.json` `scrolls`): the first win of a Nightmare last-floor boss pays 5, each later Nightmare last-floor boss kill 0.004 (paid as a fraction like the other scrolls, about one scroll an hour of farming a Nightmare boss), every 10th endless depth reached for the first time 1, the Mythic stage star chest on Nightmare 3, and each Ascension 2 from the third Ascension on. Nothing before the first Nightmare clear pays one.
- [Built] **First summon** (user, 2026-11-10). A new game starts with one Summon Scroll, one pull (`resources.json`), and its first goal is to summon your first card.
- [Built] **Cores** (Moss, Cinder, Frost) drop with a chance per kill, so every dungeon stays worth farming for its material (`dungeons.json`). **Frost Cores and Frost Sigils** drop in the Frostspire Vault and, at a low rate, in the Ember Crypt (user, 2026-11-10), so a Gold card stuck at Dungeon 3 can still grow; the Ember Crypt was chosen over the Glimmer Trial's top tiers because a stalled run never reaches the Glimmer Trial.
- [Default · in game] The Ember Crypt's Frost Core and Frost Sigil rate: one of each at 2% a kill (`dungeons.json`).

## 4. Production

- [Built] **One of each.** Each tree kind and mine type exists once and is levelled up. There are no plots or slots, no copies of the same tree or mine, and no expansions to buy (user, 2026-11-08). Every unlocked kind produces once, at its level.
- [Built] A kind produces from level 0: unlocking it starts its output at its base rate, and levels and milestones add to that.
- [Built] **Balance after plots.** Every filled plot added a full copy of a tree's output, so the base rate of every tree kind and mine type is now three times what it was (Oak 3 a second, Copper Quarry 1.5, ...; `trees.json`, `mines.json`), tuned with the sim against the pacing targets (§14). The level rule is Levels below. Old saves got back the Money they spent on plots and slots (save format 16, built): each expansion at its old price, 25 × 1.4ⁿ rounded up, before any modifier.
- [Built] **Trees.** Oak (start), Ironbark and Moonwillow, each yielding its own gem. A tree kind is unlocked once with gems of the tier below (`trees.json`).
- [Built] **Mines.** Copper Quarry (start), Iron Deeps (unlocked by clearing the Mossy Cellar) and Crystal Grotto (unlocked by clearing the Ember Crypt), each yielding its own gem.
- [Built] **Levels** (user, 2026-11-10). Each tree kind and mine type has a level bought with Money (`trees.json`, `mines.json`) and follows the classic idle shape: the cost grows by only about ×1.07 to ×1.15 per level, and more milestone multipliers (×2 to ×3) keep income close to prices. Built: the cost grows ×1.109 (Oak, Copper Quarry), ×1.117 (Ironbark, Iron Deeps) and ×1.126 (Moonwillow, Crystal Grotto) from base prices of 57, 480, 4,000 and 45, 400, 3,400 Money (§14 Readable numbers, `[Default]` of the rescale, Claude, 2026-11-12; it was ×1.13, ×1.14 and ×1.15 from 200, 2,500, 30,000 and 150, 2,000, 25,000), and the milestone ladder below.
- [Default · in game] **The milestone ladder** (Claude, 2026-11-12, table update balance pass 2). Every tree and mine multiplies its output by ×1.15 every 15 levels (readable-numbers rescale, 2026-11-12, §14: it was ×2, and every 25 levels before pass 2) and adds +5% a level between them (it was +10%), so the milestones lead the growth (`trees.json`, `mines.json`). It cannot run away: a level then raises the output by at most about ×1.01 to ×1.06 (1.15^(1/15) times the +5% step), under the ×1.055 a price still grows with every growth cut taken (§3 Price growth cuts). In the sim (8 seeds, 40 h) the next level keeps costing more of the Money income as the run goes on, 11 s at hour 1, 25 s at hour 5, 33 s at hour 20 and 81 s at hour 40, where a runaway would drive it toward nothing; the earlier try with cheap levels and ×3 milestones had done that. The richer gems are met by a larger Starlight divisor (§9). The next milestone shows on the line ("Lv 15: ×1.15") and reaching it plays a small celebration. Levels reset on Ascension.
- [Built] **Upgrade shelf.** One-time Money upgrades beside the level lines (`upgrades.json`). Each appears when its unlock is met, glows when affordable and is owned once bought; its effects are ordinary modifiers. The tree and mine upgrades multiply their output by ×1.25 and ×1.5 where they doubled and tripled it, and every Money price and lifetime-Money unlock is on the readable scale (`upgrades.json`; readable-numbers rescale, 2026-11-12, `[Default]`, §14). Per-run items reset on Ascension; permanent ones stay. Lifetime Money earned is counted and kept.
- [Built] The six shelf upgrades that were unlocked by damage-line levels (Copper, Iron and Crystal Temper and Hardening) went with the lines, and an owned one paid its Money back (save format 17). No shelf item depends on plots or damage lines.
- [Built] **Workers play the field** (user, 2026-11-11). Each working card strikes its own tree or mine with its pattern (`cards.json` `worker.harvest`: steady, chop, flurry or volley; interval and strikes per cycle) and shows "+n" per strike. Strikes are show: the economy uses the expected value, so online and offline give the same totals. A tree or mine with no worker is not struck.
- [Built] **Harvest burst.** A harvest gauge fills by 1 on every tick, once per second. At 30 it gives 10 s of output at once, played as a wave with one big total. Each worker has its own gauge for its own tree or mine (Workers below), and its burst pays that place's output.
- [Default · in game] A gauge belongs to its place: a worker sent away leaves the gauge where it is for the next one, and a place with no worker does not fill it (Claude, 2026-11-11).
- [Built] **Harvest crits.** `harvest.critChance` (base 0) and `harvest.critDamage` (base ×2), read at a worker's place through the modifier pipeline, so they come from the card working there (its ability and enhancements). Gem Cutter's ability and the Keen Eye enhancement grant a chance today.
- [Default · in game] A tree or mine with no worker has no crits (Claude, 2026-11-11).
- [Built] **Gem mastery.** Each gem's lifetime harvest gives a mastery tier at 1,000 / 23,000 / 520,000 / 12 million (bronze to prismatic; readable-numbers rescale, `[Default]`, 2026-11-12: it was 1e3 / 1e5 / 1e7 / 1e9), +10% to that gem per tier, kept through Ascension. The gem's coin shows the tier in its metal.
- [Default · in game] Gem mastery gets more tiers above the fourth for the larger production (Claude, 2026-11-11). Built: eight thresholds, 1,000 up to 3.3 trillion (`progression.json`; they were 1e3 up to 1e17, mapped onto the readable scale on 2026-11-12, §14); the tiers above Prismatic keep the Prismatic coin and give the same +10% each.
- [Built] Every gem from production counts as harvested, harvest bursts included; mastery tiers take effect on the next whole second so any split of time gives the same totals.
- [Built] **Workers** (user, 2026-11-11). Logging and mining cards are workers. A card is placed on one tree kind or mine type and harvests it by itself, and what it brings in comes from the card's own stats: its power (rarity, level, tier and stars) multiplies that tree's or mine's output, its hit speed sets the strike rhythm and its crits are harvest crits. Workers replace the logging and mining loadouts (§5 Loadouts): those jobs have no main card, no supports and no cost cap. A tree or mine with no worker still produces at its plain level rate. A card works one place at a time. There are no worker sprites: the cards themselves are the workers, and pixel workers stay cut.
- [Default · in game] **Worker slots** (Claude, 2026-11-11; the user asked for limits that unlock step by step and left the pace to Claude). One worker per tree kind or mine type. A new game has two slots, one for logging and one for mining; each Ascension opens one more until every tree and mine has one (six today; `production.json` `workers.slots`). The slots are shared by both jobs, and when there are more workers than slots the first places in order (trees, then mines) keep theirs and the rest wait, never a broken assignment. Each tree and mine can then open a second slot, bought in the Starlight shop (§9), for twelve workers at most; the cap grows if trees or mines are added. In an old save each job's main card becomes its first worker.
- [Default · in game] **Worker abilities** (Claude, 2026-11-11). Every logging and mining card's main ability and support effect are rewritten as one worker ability that acts on the tree or mine it works (`cards.json`), and their enhancements likewise (`enhancements.json`: Thrift became Keen Eye, a harvest crit chance). The shelf upgrades that boosted production supports, Lumberjack Pact and Miner Pact, make worker abilities 25% stronger (`upgrades.json`).
- [Default · in game] **Worker power** (Claude, 2026-11-11). A worker's power is its rarity's power (1, 1.14, 1.33, 1.52, 1.77, 2.12 for Common to Mythic/Void, `production.json`; readable-numbers rescale, 2026-11-12: it was 1, 1.25, 1.6, 2, 2.6, 3.5) × its level, star and tier power, the same as its base stats grow with. Its ability applies as written and does not grow with the power (the power already multiplies the output). The two start Commons' ability is +20% card XP at their place, so a new game produces exactly as before. A worker gains XP from its own place's harvest only: 30 XP a gem of a tree and 60 of a mine (`cardRules.json` `xp.perUnit`; readable-numbers rescale, 2026-11-12, `[Default]`: it was 1 and 2, raised because the gems came down).
- [Built] **Tool lines** (user, 2026-11-11). Each production job has repeatable upgrade lines bought with Money, like Training (§6): yield, strike speed, crit chance and crit damage (`production.json` `tools`, levels in `production.tools`). They are the source of harvest crit chance. ×1 / ×10 / ×100 / Max buys them and an Ascension resets them.
- [Default · in game] Yield and strike speed multiply their stat by (1 + rate% × level) × a milestone multiplier every 25 levels, like Training (yield +4% a level and ×1.1, strike speed +2% and ×1.08; the readable-numbers rescale's `[Default]`, 2026-11-12, §14: they were +8% and ×1.5, +4% and ×1.25); crit chance adds percentage points a level and crit damage adds to the ×2 of a crit, with no milestones. Strike speed also speeds the harvest gauge and the digging (Claude, 2026-11-11).
- [Built] **Depth and growth** (user, 2026-11-11). Each mine has layers to dig down through and each tree has ages to grow through (`depth` in `trees.json`, `mines.json`; `production.depth`). A deeper layer or an older tree yields richer gems but has a hardness to break through first, and the worker's damage is what breaks it, as a fighting card's damage breaks an enemy's health. Each tree and mine shows its own depth or age on its row, with a bar to the next.
- [Default · in game] **How depth works** (Claude, 2026-11-11). A layer's hardness grows by a factor a layer (×1.95, and a broken layer multiplies the yield by ×1.15: the readable-numbers rescale's `[Default]`, 2026-11-12, §14; they were ×2.2 and ×1.6); the worker breaks `digRate` hardness a second × its power × its strike speed, so a place with no worker does not dig; breaking a layer multiplies the place's yield by `yieldGrowth`, and the deepest layer is never broken. The layer changes on the 1 s play-time grid like card levels, so any split of time gives the same totals.
- [Built] **The forge** (user, 2026-11-11). A place that spends gems to make something else, so late gems have a use (`production.json` `forge`, state `production.forge`). It takes a worker, and a stronger card refines faster. One recipe makes star dust (§5), at a rare rate.
- [Default · in game] **How the forge works** (Claude, 2026-11-11). One recipe at a time: progress a second is the forge's speed × the worker's power, and each time it reaches the recipe's work the inputs are spent and the output made, whole. Any production card can work it and it uses one of the shared worker slots, filled after the trees and mines, so a full house sends its worker away first. Waiting for gems banks at most one craft of work.
- [Built] **Lucky strikes** (user, 2026-11-11). Now and then a rich vein or a golden tree appears on a tree or mine for a short time, and the card working there strikes it for a large payout (`production.json` `lucky`). Offline progress gets the average.
- [Default · in game] **How lucky strikes work** (Claude, 2026-11-11). A worked place gets one every few minutes, shown for about ten seconds, and pays some seconds of its output; the economy adds the average (output × (1 + payout / interval)) and nothing is rolled, so online, offline and any split of time agree, and the stage plays the strikes from the play-time clock. A place with no worker has none.
- [Default] The numbers of the tool lines, the layers and ages, the forge's recipes (star dust, §5, among them) and how often a lucky strike comes (`production.json`, `trees.json`, `mines.json`) were measured in the balance run (2026-11-11) and kept: at 40 hours the sim's tool lines sit near level 40 to 50, the forge makes star dust whenever a card needs stars, and workers fill 7 of 10 slots (2 until the first Ascension at about 8 hours). An Ascension resets depth and age as it resets levels, and the tool lines and harvest gauges with them; it keeps the workers where they are and the forge with its recipe, worker and progress (Claude, 2026-11-11). A new game starts with its logging and mining start cards working the first tree and the first mine, as an old save's main cards do.
- [Built] **Screen: wings and job views** (user, 2026-11-11, the one-table layout, mockups 4a, 4c and 4e; replaces the pixel ledger page). Logging and Mining are two wings on the table, beside the dungeon window: each shows the job's output, one small plate per tree kind or mine type (output, level, next price, its worker and its age or layer) and its tools. - [Built] **Loadout presets.** Each dungeon remembers its own fighting loadout and switches to it when picked; production jobs get named presets.
- [Default · in game] Three presets per production job (name, Use, Save here, Clear on each production band). The dungeon's loadout is remembered when you leave it; a dungeon with nothing remembered keeps the current loadout; a remembered card that is gone or away leaves its slot empty; a loadout over the cost cap is flagged and not applied, never deleted. Workers have slots, not a cost cap (0.6.0), so a worker preset that needs more slots or places than are open is applied as far as it fits and flagged with how many did not fit; it stays saved as it was.
- [Built] **Bonds.** Specific pairs of cards in the same loadout unlock a small named bonus. An undiscovered bond shows as a silhouette in a Codex until first triggered; a pixel chain links the two cards on the table.
- [Default · in game] Oath of Dawn (Ember Squire + Dawnblade Regent: +2 burst fill per hit), Old Growth (Apprentice Feller + Elder Treant: harvest bursts +5 s), Deep Vein (Cave Digger + Geode Golem: +15% mining). The bonus enters through the modifier pipeline (source `bond`) and a bond is discovered the first time it is active, recorded on the 1 s grid.
- [Built] **Expeditions.** Cards not in a loadout go on timed trips to places opened by clearing dungeons and bring back that area's materials, some gems and card XP, double for a matching element. They are plain timers outside the offline cap. A card on a trip cannot be equipped.

- [Built] **Ascension challenges.** After the first Ascension, a challenge is an Ascension run with a rule, completed by clearing a target under that rule, up to three times with harder targets, each completion giving a permanent reward. - [Default · in game] **How challenges work** (Claude, table update). Starting one is an Ascension (it needs the same 10 Starlight and grants it) whose run follows the rule, with the target dungeon's tier back on floor 1 so the half-start cannot finish it. A target is reached when the run stands on its floor; the rule then ends, the run goes on as a normal one and the reward is kept. Leaving a challenge ends the rule at once and earns nothing; an Ascension that is not a challenge ends it too. The next target is the next of the three, and the target dungeon must be open. The rules are applied through the modifier pipeline, never in the fight: a card left out (Lone Wolf, Common Folk) loses its effect and its health, and a main left out deals no damage. Rewards are modifiers of source `challenge` (`challenges.json`): damage, card XP, Money per kill, production, health and worker power.

- [Default · in game] **How the autobuyers work** (Claude, 2026-11-11). Each is bought once in the Starlight shop and has its own on / off switch; one reserve (0 to 100%) is shared.
