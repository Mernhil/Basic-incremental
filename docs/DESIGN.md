# Basic Incremental — Game Design

The source of truth for the game's design. It holds one version of every rule: the current one. Anything not covered here is an open question for the user.

## How this document works

Every rule starts with a status tag:

| Tag          | Meaning                                                                                                                                 |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| `[Built]`    | Decided by the user and in the game as written.                                                                                         |
| `[Differs]`  | Decided by the user. The game has it but works differently: the text is the target, and the rule says what the game does today.         |
| `[To build]` | Decided by the user, not in the game yet.                                                                                               |
| `[Default]`  | Filled in by Claude; the user has not decided it. `[Default · in game]` when it is built. Every default is listed under Open questions. |
| `[Proposed]` | Suggested in a chat and waiting for the user's answer. Not built. Every proposal is listed under Open questions.                        |

Rules for keeping this file clean (they also bind every Claude session, in claude.ai and in Claude Code):

1. **One version of each rule.** This file holds only the current design. A change rewrites the rule where it lives. Never add amendment, update, addendum or "defaults" sections, and never leave an old version next to the new one.
2. **Every rule has a tag.** `npm run lint` runs `scripts/check-design.mjs`, which fails when a rule has no tag or an amendment-style section appears, so CI blocks it.
3. **Only the user decides.** When something is missing, Claude asks. If work cannot wait, Claude writes its choice where the rule belongs, tagged `[Default]`, and lists it under Open questions; it stays a default until the user confirms it. Claude never changes a decision of the user's on its own: a tuning that needs to break one is a question, not an edit.
4. **Decisions reach the repo first.** A decision made in a claude.ai chat is written as edits to this file. The prompt for Claude Code starts with those edits, and Claude Code commits them before any code. A chat decision that is not in this file is not a decision yet.
5. **Tags move with the code.** A PR that builds or changes a rule updates its tag in the same PR (`[To build]` or `[Differs]` becomes `[Built]`). A rule the game no longer matches is never left `[Built]`.
6. **Rules, not tuning.** Exact tuning numbers live in `src/data/content`, and the rule names the file. This file keeps the rules, the targets and the numbers the user decided. Tuning stories go in the PR description.
7. **Changelog.** A changed or dropped rule gets one dated line at the end: what changed and who decided it.
8. **Say where things stand.** Asked whether something exists, Claude answers with its tag (built, differs, to build, default, proposed), never just "it already exists".

The layered version this file replaced (sections 11 and 12 as amendments) is in git history at commit `ac33acd`.

## 1. The game

- [Built] A Windows desktop incremental about collectible cards: two production jobs (logging and mining) and auto-fought dungeons, with a gacha for cards and cosmetics. Customization is the main feature. Made mainly for the user, maybe for others.
- [Built] **Brave Frontier is the main reference** for style, screen order, upgrades, the evolution feel and the gacha, adapted to a desktop app: no characters as cards, no turn-based combat, no energy or stamina timers.
- [Built] **Three loops** (§3): dungeons pay Money and crystals, production pays materials, and both are spent on cards and cosmetics.

## 2. Distribution, saves and tools

- [Built] A Windows `.exe` built with Electron and TypeScript; unsigned is fine. Pushing a version tag (`vX.Y.Z`) builds it in GitHub Actions and publishes a GitHub Release. The app checks for updates on launch.
- [Built] **Saves** are JSON on disk with autosave and export / import. They are versioned: every format change bumps the version and adds a migration.
- [Built] **Offline progress** follows the same rules as online play and is capped at about 8 hours.
- [Built] **Dev tools** (user, 2026-11-10). Dev builds take `BI_PROFILE` / `--bi-profile` or `BI_USER_DATA_DIR` so parallel dev apps never autosave over each other. Dev cheats are pure functions in the separate `game/dev` entry, allowed only in unpackaged builds (the main process reports it), and `npm run build` fails if a release bundle contains them. A small dev cheats panel, present in dev builds only, calls those `game/dev` functions (Ctrl+Shift+D or its "Dev" button: resources, dungeon clears, a card's rank, account XP, cosmetics, time); it never ships in a release build.
- [Built] **Report an issue** opens a pre-filled GitHub issue with the app version, a save summary, OS and Electron versions and the last log lines, kept under about 7,500 characters. The player can edit it before submitting.

## 3. Economy: the three loops

- [Built] **Money comes only from dungeons**: a wage per second while fighting the first dungeon's boss (not while knocked out) and a purse on every kill in every dungeon (`dungeons.json`). A new game starts with 100 Money. Its display name lives only in `resources.json`.
- [Built] **Money buys** tree and mine levels, the upgrade shelf (§4) and weapon tier-ups (§5). The three damage lines it used to buy are gone (§5).
- [Built] Every Money price is a curve `base × growth^n` in the data files, read through `cost.multiplier` and `cost.growth`.
- [Default · in game] **Price growth cuts never stop a price growing** (Claude, 2026-11-11, balance run). A `cost.growth` cut (Wide Skies, Fresh Start, Wide Groves, Deep Roots) takes its percent off the part of the growth above 1, so −10% turns ×1.2 into ×1.18, and all the cuts together take at most half of it (`MAX_GROWTH_CUT` in `production.ts`). Before, the cuts added up to 15% on mines and 36% on trees, took ×1.13 down to the floor of 1, and levels stopped costing more: Money ran away after about 58 hours.
- [Built] **Coins** (user, 2026-11-10: "upgrading coins instead of mathematical numbers"). Money is shown in the biggest coin it fills instead of a long or scientific number: 950 is "950 Copper", 12,400,000 is "12.4 Gold". The header chip shows the count, names the coin and tints its coin to match; prices, purses and offline gains in Money read the same way. Display only: the game still counts Money as one number, and nothing is exchanged. The coins are data (`coins.json`); past the last coin its count keeps growing in the number style of Settings.
- [Built] The coin ladder (`coins.json`; Claude's proposal, confirmed by the user on 2026-11-10): Copper, Silver, Gold, Diamond, Star, Moon, Sun, Crown, each worth 1,000 of the one before (Silver from 1,000 Money, Gold from a million, Diamond from a billion). Counts show three digits, rounded down. The user's example steps (silver at 1,000, gold at 10,000, diamond at a million) were uneven; even steps of 1,000 keep every count between 1 and 999. The coin colours are recolours of the one coin sprite, not new art. The Money rate under the header chip stays a plain number per second.
- [Built] **Ladders** (user, 2026-11-10; between dungeons changed 2026-11-11). Inside a dungeon the ladder grows at one steady rate: every floor is ×1.12 the HP and attack of the one above, ending on the boss as `dungeons.json` has it, and an enemy's purse is its share of the boss's HP, so purses follow the same rate, with 2% more for every floor deeper (§6 Deeper pays more; `combat.json` `floors`). The same floor rate carries on through the difficulty tiers and the endless depths (§6). Between dungeons the pacing targets (§14) win over a steady rate (user, 2026-11-11: "keep the targets"): a steady rate cannot meet them, because power grows fast in the first hours (three tiers by hour 4) and slowly after (one tier between hours 4 and 25), while the targets put 60 floors in the first 12 hours and 150 in the next 24. So each boss is set from the targets (balance run, 2026-11-11): Root Warden 45,000 HP, Cinder Lich 2.5 million, Glacier Colossus 400 million, Storm Roc 800 million, Dawn Hierophant 3 billion and The Unmade King 6 billion, attack and purses in step with the HP (a boss purse is about a tenth of its HP in Money). Bosses climb ×50 to ×160 a dungeon early and ×2 to ×4 late, and the first floors of Dungeons 4 to 6 sit below the boss before them. Tier-ups should cost about the same amount of play time at each step (§5); tier-up Money is unchanged (20k, 60k, 2M, 10M, 50M, 100M) and not measured as equal play time per step.
- [Built] **Production pays materials only**: the six gems. Gems, Cores, Frost Sigils, Glimmer Dust and Facet Shards pay for card upgrades, cosmetic upgrades and tree unlocks. Nothing in production pays Money.
- [Built] **Crystals are the premium tier.** The Summon Crystal pays for the Card Portal and the Glamour Crystal for the Wardrobe Gate. Only the portals spend them, and Ascension keeps them.
- [Differs] **Crystal wage** (user, 2026-11-10). Crystals come as a wage while fighting a dungeon (not while knocked out), not per kill, so pulls no longer grow with kill speed. Each dungeon pays its own wage of both crystals (`dungeons.json`). Crystal purses stay only on a dungeon's first clear, and later on stage stars and chests (§6, Scope 3). **Scrolls replace it** (user, 2026-11-10 gameplay brainstorm: summoning "more like AFK"; picked "Summon scrolls"): pulls are paid with scrolls that come in lumps and are saved up, one scroll for one pull, Summon Scrolls for the Card Portal and Glamour Scrolls for the Wardrobe Gate; nothing ticks in per second. Scrolls come from the first win of a Challenge floor, from bosses, goals, achievements and a daily reward. Today the wage above is in the game.
- [Default] Scroll details: crystals a save holds become scrolls at the pull price (300 crystals for one scroll, rounded down), and a new game starts with one Summon Scroll, its one free pull; every price and reward in crystals is divided the same way; the amounts per source are set with the sim to keep the pull pace of §7. Scrolls are kept through Ascension, as crystals are.
- [Default · in game] The wage amounts and the first-clear purses (`dungeons.json`): 0.5, 0.6 and 0.7 Summon Crystals and 0.4, 0.45 and 0.55 Glamour Crystals a second from the first to the third dungeon; first clears pay 300 / 150, 900 / 600 and 1,500 / 900. The user picked this middle wage on 2026-11-10 over a lower one that held 12 to 15 pulls an hour but pushed Dungeon 3 to about 27 h (§7, §14).
- [Built] **First summon** (user, 2026-11-10). A new game starts with enough Summon Crystals for one pull (`resources.json`), and its first goal is to summon your first card.
- [Built] **Cores** (Moss, Cinder, Frost) drop with a chance per kill, so every dungeon stays worth farming for its material (`dungeons.json`). **Frost Cores and Frost Sigils** drop in the Frostspire Vault and, at a low rate, in the Ember Crypt (user, 2026-11-10), so a Gold card stuck at Dungeon 3 can still grow; the Ember Crypt was chosen over the Glimmer Trial's top tiers because a stalled run never reaches the Glimmer Trial.
- [Default · in game] The Ember Crypt's Frost Core and Frost Sigil rate: one of each at 2% a kill (`dungeons.json`).

## 4. Production

- [Built] **One of each.** Each tree kind and mine type exists once and is levelled up. There are no plots or slots, no copies of the same tree or mine, and no expansions to buy (user, 2026-11-08). Every unlocked kind produces once, at its level.
- [Built] A kind produces from level 0: unlocking it starts its output at its base rate, and levels and milestones add to that.
- [Built] **Balance after plots.** Every filled plot added a full copy of a tree's output, so the base rate of every tree kind and mine type is now three times what it was (Oak 3 a second, Copper Quarry 1.5, ...; `trees.json`, `mines.json`), tuned with the sim against the pacing targets (§14). The level rule is Levels below. Old saves got back the Money they spent on plots and slots (save format 16, built): each expansion at its old price, 25 × 1.4ⁿ rounded up, before any modifier.
- [Built] **Trees.** Oak (start), Ironbark and Moonwillow, each yielding its own gem. A tree kind is unlocked once with gems of the tier below (`trees.json`).
- [Built] **Mines.** Copper Quarry (start), Iron Deeps (unlocked by clearing the Mossy Cellar) and Crystal Grotto (unlocked by clearing the Ember Crypt), each yielding its own gem.
- [Differs] **Levels** (user, 2026-11-10). Each tree kind and mine type has a level bought with Money (`trees.json`, `mines.json`) and follows the classic idle shape: the cost grows by only about ×1.07 to ×1.15 per level, and more milestone multipliers (×2 to ×3) keep income close to prices. Built: the cost grows ×1.13 (Oak, Copper Quarry), ×1.14 (Ironbark, Iron Deeps) and ×1.15 (Moonwillow, Crystal Grotto) from base prices ten times the old ones. Not built yet: more milestone multipliers; output is still +10% per level and ×2 every 25 levels (cheap levels with ×3 milestones made production run away in the sim). The next milestone shows on the line ("Lv 25: ×2") and reaching it plays a small celebration. Levels reset on Ascension.
- [Built] **Upgrade shelf.** One-time Money upgrades beside the level lines (`upgrades.json`). Each appears when its unlock is met, glows when affordable and is owned once bought; its effects are ordinary modifiers. Per-run items reset on Ascension; permanent ones stay. Lifetime Money earned is counted and kept.
- [Built] The six shelf upgrades that were unlocked by damage-line levels (Copper, Iron and Crystal Temper and Hardening) went with the lines, and an owned one paid its Money back (save format 17). No shelf item depends on plots or damage lines.
- [Built] **Workers play the field** (user, 2026-11-11). Each working card strikes its own tree or mine with its pattern (`cards.json` `worker.harvest`: steady, chop, flurry or volley; interval and strikes per cycle) and shows "+n" per strike. Strikes are show: the economy uses the expected value, so online and offline give the same totals. A tree or mine with no worker is not struck.
- [Built] **Harvest burst.** A harvest gauge fills by 1 on every tick, once per second. At 30 it gives 10 s of output at once, played as a wave with one big total. Each worker has its own gauge for its own tree or mine (Workers below), and its burst pays that place's output.
- [Default · in game] A gauge belongs to its place: a worker sent away leaves the gauge where it is for the next one, and a place with no worker does not fill it (Claude, 2026-11-11).
- [Built] **Harvest crits.** `harvest.critChance` (base 0) and `harvest.critDamage` (base ×2), read at a worker's place through the modifier pipeline, so they come from the card working there (its ability and enhancements). Gem Cutter's ability and the Keen Eye enhancement grant a chance today.
- [Default · in game] A tree or mine with no worker has no crits (Claude, 2026-11-11).
- [Built] **Gem mastery.** Each gem's lifetime harvest gives a mastery tier at 1e3 / 1e5 / 1e7 / 1e9 (bronze to prismatic), +10% to that gem per tier, kept through Ascension. The gem's coin shows the tier in its metal.
- [Default · in game] Gem mastery gets more tiers above 1e9 for the larger production (Claude, 2026-11-11). Built: eight thresholds, 1e3 up to 1e17 (`progression.json`); the tiers above Prismatic keep the Prismatic coin and give the same +10% each.
- [Built] Every gem from production counts as harvested, harvest bursts included; mastery tiers take effect on the next whole second so any split of time gives the same totals.
- [Built] **Workers** (user, 2026-11-11). Logging and mining cards are workers. A card is placed on one tree kind or mine type and harvests it by itself, and what it brings in comes from the card's own stats: its power (rarity, level, tier and stars) multiplies that tree's or mine's output, its hit speed sets the strike rhythm and its crits are harvest crits. Workers replace the logging and mining loadouts (§5 Loadouts): those jobs have no main card, no supports and no cost cap. A tree or mine with no worker still produces at its plain level rate. A card works one place at a time. There are no worker sprites: the cards themselves are the workers, and pixel workers stay cut.
- [Default · in game] **Worker slots** (Claude, 2026-11-11; the user asked for limits that unlock step by step and left the pace to Claude). One worker per tree kind or mine type. A new game has two slots, one for logging and one for mining; each Ascension opens one more until every tree and mine has one (six today; `production.json` `workers.slots`). The slots are shared by both jobs, and when there are more workers than slots the first places in order (trees, then mines) keep theirs and the rest wait, never a broken assignment. Each tree and mine can then open a second slot, bought in the Starlight shop (§9), for twelve workers at most; the cap grows if trees or mines are added. In an old save each job's main card becomes its first worker.
- [Default · in game] **Worker abilities** (Claude, 2026-11-11). Every logging and mining card's main ability and support effect are rewritten as one worker ability that acts on the tree or mine it works (`cards.json`), and their enhancements likewise (`enhancements.json`: Thrift became Keen Eye, a harvest crit chance). The shelf upgrades that boosted production supports, Lumberjack Pact and Miner Pact, make worker abilities 25% stronger (`upgrades.json`).
- [Default · in game] **Worker power** (Claude, 2026-11-11). A worker's power is its rarity's power (1, 1.25, 1.6, 2, 2.6, 3.5 for Common to Mythic/Void, `production.json`) × its level, star and tier power, the same as its base stats grow with. Its ability applies as written and does not grow with the power (the power already multiplies the output). The two start Commons' ability is +20% card XP at their place, so a new game produces exactly as before. A worker gains XP from its own place's harvest only.
- [Built] **Tool lines** (user, 2026-11-11). Each production job has repeatable upgrade lines bought with Money, like Training (§6): yield, strike speed, crit chance and crit damage (`production.json` `tools`, levels in `production.tools`). They are the source of harvest crit chance. ×1 / ×10 / ×100 / Max buys them and an Ascension resets them.
- [Default · in game] Yield and strike speed multiply their stat by (1 + rate% × level) × a milestone multiplier every 25 levels, like Training; crit chance adds percentage points a level and crit damage adds to the ×2 of a crit, with no milestones. Strike speed also speeds the harvest gauge and the digging (Claude, 2026-11-11).
- [Built] **Depth and growth** (user, 2026-11-11). Each mine has layers to dig down through and each tree has ages to grow through (`depth` in `trees.json`, `mines.json`; `production.depth`). A deeper layer or an older tree yields richer gems but has a hardness to break through first, and the worker's damage is what breaks it, as a fighting card's damage breaks an enemy's health. Each tree and mine shows its own depth or age on its row, with a bar to the next.
- [Default · in game] **How depth works** (Claude, 2026-11-11). A layer's hardness grows by a factor a layer; the worker breaks `digRate` hardness a second × its power × its strike speed, so a place with no worker does not dig; breaking a layer multiplies the place's yield by `yieldGrowth`, and the deepest layer is never broken. The layer changes on the 1 s play-time grid like card levels, so any split of time gives the same totals.
- [Built] **The forge** (user, 2026-11-11). A place that spends gems to make something else, so late gems have a use (`production.json` `forge`, state `production.forge`). It takes a worker, and a stronger card refines faster. One recipe makes star dust (§5), at a rare rate.
- [Default · in game] **How the forge works** (Claude, 2026-11-11). One recipe at a time: progress a second is the forge's speed × the worker's power, and each time it reaches the recipe's work the inputs are spent and the output made, whole. Any production card can work it and it uses one of the shared worker slots, filled after the trees and mines, so a full house sends its worker away first. Waiting for gems banks at most one craft of work.
- [Built] **Lucky strikes** (user, 2026-11-11). Now and then a rich vein or a golden tree appears on a tree or mine for a short time, and the card working there strikes it for a large payout (`production.json` `lucky`). Offline progress gets the average.
- [Default · in game] **How lucky strikes work** (Claude, 2026-11-11). A worked place gets one every few minutes, shown for about ten seconds, and pays some seconds of its output; the economy adds the average (output × (1 + payout / interval)) and nothing is rolled, so online, offline and any split of time agree, and the stage plays the strikes from the play-time clock. A place with no worker has none.
- [Default] The numbers of the tool lines, the layers and ages, the forge's recipes (star dust, §5, among them) and how often a lucky strike comes (`production.json`, `trees.json`, `mines.json`) were measured in the balance run (2026-11-11) and kept: at 40 hours the sim's tool lines sit near level 40 to 50, the forge makes star dust whenever a card needs stars, and workers fill 7 of 10 slots (2 until the first Ascension at about 8 hours). An Ascension resets depth and age as it resets levels, and the tool lines and harvest gauges with them; it keeps the workers where they are and the forge with its recipe, worker and progress (Claude, 2026-11-11). A new game starts with its logging and mining start cards working the first tree and the first mine, as an old save's main cards do.
- [Differs] **Screen: pixel ledger** (user, 2026-11-10; replaces the side stage). Logging and Mining are two stacked bands, each in its own pixel frame (§11). Each band has the rows, one per tree kind or mine type: the card working it with its harvest gauge (a click opens the worker picker under the row), the tile (it grows with level), name, level, output per second, a segmented bar to the next ×2 milestone, a "next buy" column and the buy button with its preview. The "next buy" column shows the wait until the next level is affordable, or "ready" and the output gain when it is affordable now. The band's title line says how many worker slots are in use. A locked kind is a greyed row with its unlock price on the button (a locked mine names the dungeon to clear). One ×1 / ×10 / ×100 / Max toggle sits at the right end of the goals strip. Each worker nudges toward its own tile when it strikes and "+n" pops on that row; a burst runs a wave over the places whose gauge fired. The upgrade shelf is a drawer over the bottom: closed it is one line (how many upgrades are ready to buy and how many are owned). Picked by the user from the round-2 mockups (option 1a, "Pixel ledger"). The tool lines, depth or age, the forge and lucky strikes have plain working screens in this layout (`docs/UI_RULES.md`). Built: the workers on the rows, as a chip with the card's name, level and power, not yet the card art.
- [Built] The shelf drawer starts open on a window at least 900 px tall and closed on a shorter one, then keeps the player's choice; "ready" counts the upgrades the player can afford now.
- [Built] **Next buy wording.** The wait shows as days and hours ("9d 3h"), hours and minutes ("1h 49m"), minutes and seconds ("12m 5s") or seconds ("40 s"); no income shows "—"; an affordable level shows "ready" and its output gain as a multiplier ("×1.03 output").

## 5. Cards and weapons

### Cards

- [Built] **Job-specific.** Logging, mining and fighting cards; a card only works in its own job.
- [Differs] **Item types** (user, 2026-11-09). Fighting cards carry a weapon (sword, greatsword, spear, lance, dagger, hammer, bow, staff, scythe), mining cards a pickaxe and logging cards a logging axe: 11 types. Every item is remade from scratch; the old kinds (twin blades, hatchet, maul, chisel, geode hammer, gauntlet) leave the game. Built: the types, their names and the data (`items.json`). The new pictures are not drawn yet: each type shows an interim look (Weapon looks below).
- [Built] **Loadouts** (user, 2026-11-11). Only fighting has a loadout: 1 main card and 3 support cards, any fighting card in any slot, once per loadout. Every fighting card has a main ability (used when it leads) and a support effect (used as a support). Logging and mining cards are workers (§4).
- [Built] **Rarity.** Common, Uncommon, Rare, Epic, Legendary and Mythic/Void. Mythic and Void are one top rarity with two sides, equal in power and differing only in look: Mythic the heroic side, Void the villain side (user, 2026-11-09). Rarity sets the colour of the card body: steel grey, green, blue, purple, amber, then neon pink for Mythic and black chrome for Void. The job is a label, not a colour.
- [Built] **Uncommon and Mythic/Void numbers.** The Uncommon body is green, and every rarity-keyed number for Uncommon sits between Common and Rare. Mythic and Void share one value in every rarity-keyed number (cost, base stats, health, shards, star bar, cosmetic level), tuned with the sim; Mythic keeps the neon pink body, Void the black chrome.
- [Built] **Cost.** Each card costs by rarity (`cardRules.json`, Common 2 to Mythic/Void 14) and the fighting loadout has a cost cap that grows with account level (§10). A loadout over the cap cannot be saved.
- [Built] **Uncommon and Mythic/Void costs.** Common 2, Uncommon 3, Rare 4, Epic 6, Legendary 9 and Mythic/Void 14 (`cardRules.json`).
- [Built] **Start.** A new game owns Ember Squire, Apprentice Feller and Cave Digger at Wood ★1, Lv 1: the Squire leads the fighting loadout, the Feller works Oak and the Digger the Copper Quarry.
- [Built] **Collection.** Each card is owned once; further copies are stored on it as duplicates. Duplicates past the last star become shards for the shard shop (§10), more for higher rarities.
- [Built] **Abilities.** Fighting mains shape how damage is dealt (steady ticks, fast hits that fill the gauge quickly, slow heavy hits with a stronger signature attack). Fighting supports add a percentage or a gauge, drop or material bonus. A worker's one ability shapes its own place's output, gauge or crits, and its pattern sets how it strikes (§4 Worker abilities). Every card effect goes through the modifier pipeline (source `card`).
- [Built] **Full-art layout** (user, 2026-11-10: confirmed as built). The card's signature item fills the whole card. Top plate: name and stars side by side, nothing else. Bottom plate: ability name and hit speed on one line, level and the rarity word on the next, then the progress bar. No separate chips elsewhere on the art. The tier frame (§12 frame ladder) and the cosmetic border/finish slots (§8) apply over this layout unchanged. Reference: Design canvas "Full-art weapon card concepts" at https://claude.ai/artifact/52eC1yo35gn16NrDp5btik, artboard G is the one to build; boards A-F are the trail, not alternatives (user, 2026-11-08).

### Weapon progression

_Decided with the user on 2026-11-08. It is a gacha game: strength comes from the cards you own and how far you have taken them._

- [Built] **Strength comes from cards.** The card's rarity sets its base stats (damage and health), support cards are the passives, and the main card's weapon is the only fighting upgrade.
- [Built] **No damage lines.** Copper Edge, Iron Edge and Crystal Edge, their milestones, goals, tier-up moments, bulk buys and previews are gone (user, 2026-11-08). Fighting damage is the main card's base damage (below), then the modifier pipeline (supports, tree, mastery, crits, bursts). Training (§6, user, 2026-11-10) is the repeatable fighting upgrade that came later: four lines that multiply what the cards give; the three old lines stay gone.
- [Built] **Base stats by rarity.** Each card has a base damage and a base health set by its rarity, with the same ratios (`cardRules.json`; the ratios are in the Base damage rule below). Fighting damage is the main card's base damage × its power (level, tier and stars); with no card leading, a bare-hands damage applies (`combat.json`).
- [Built] **Level.** XP from fighting or harvesting raises the weapon's level, up to its tier's cap. Every level adds the small bump, and milestone levels (every 20) open new enhancement options on the card (Enhancements below; user, 2026-11-11). No resource buys a level.
- [Differs] **Tier.** At max level and ★6, Money plus materials upgrade the weapon to the next tier. The ladder is T1 Wood → T2 Bronze → T3 Silver → T4 Gold → T5 Prismatic → T6 Mythic or Void (by the card's side), then the Heirloom (user, 2026-11-09). The stars then restart at ★1 with an empty star bar (a Wood ★6 becomes a Bronze ★1), so every tier is starred up again; the level stays and only its cap rises. Each tier gives the weapon a new look, a new frame, a higher level cap and a power step. Built: the six tiers and the Heirloom with the tier-ups paid with Money, Cores, gems and Frost Sigils (Tier-up costs below), the star reset, the frame, the cap, the power step, and the checklist and goal tracker; the new look of each tier is not drawn yet (Weapon looks below).
- [To build] **Tier looks** (user, 2026-11-09), written in full in `docs/ASSET_RULES.md` §2. T1 to T5 share one base model per item type in each material (wood, bronze, silver, gold, a crystal-like Prismatic). Upgrades 1 to 3 (T2 to T4) each upgrade one part of the item, drawn per tier in that tier's material, not a recolour of the previous tier's part; which part is in the parts table of `ASSET_RULES.md` §2 (sword: grip, then crossguard, then pommel; and so on for every type). Upgrades 4 and 5 (T5 and T6) are not tied to one part: they may reshape the whole item without replacing it and add effects and animation. T5 is deliberately less cool and less powerful than T6, so the top tier is the goal. T6 has a Mythic (heroic) and a Void (villainous) version, and the Heirloom is a separate fixed design above it.
- [Built] **Item names** (user, 2026-11-09). T1 to T4 are "<material> <type>": Wooden Sword, Bronze Sword, Silver Sword, Golden Sword (Wooden Axe for the logging axe, "Axe" in every item name). T5 is "Prismatic <name> <type>" (Prismatic Dancer Sword) and T6 "Mythic/Void <name> <type>" (Mythic Light Sword, Void Shadow Sword). Heirlooms have their own names (Solaris and Nightfall for the sword). The names of all 11 types are in `ASSET_RULES.md` §2 and, once built, in `items.json`.
- [Built] **Rarity caps the tier** (user, 2026-11-09). Common reaches T1, Uncommon T2, Rare T3, Epic T4, Legendary T5, and Mythic/Void T6 and the Heirloom. Copies past ★6 of a card's top tier become shards like any duplicate past the last star.
- [Built] **Stars** (user, 2026-11-11). Every card starts at ★1, at every rarity. Duplicates fill the card's star bar and a full bar buys a star; star dust (below) can stand in for a missing copy. Stars are the weapon's prestige: they raise its base damage and health (Star impact below). A tier-up needs all six stars and resets them (Stars restart on tier-up below). A save keeps the stars its cards already have.
- [Built] **Stars get dearer by tier** (user, 2026-11-11). A star costs a fraction of a copy at the low tiers and a whole copy only at the card's top tier, so tier-ups in the middle of the game are not held back by pull luck and the long hunt sits at the top, on the best a card can be. A fully maxed weapon, a Mythic or Void Heirloom at ★6, takes 200 hours at most for now (§14).
- [Built] **Heirloom** (user, 2026-11-09). "Unique" is renamed Heirloom everywhere. The Heirloom is the pinnacle of the weapon: a separate fixed design with the strongest effects, reached by a tier-up after T6. Every item type (11) has a Mythic and a Void Heirloom, shown by the card's side. The Heirloom tier is built and open for every type so playtests and balance can reach it (user, 2026-11-09); each shows its own approved picture per type and side (ASSET_RULES §5, Heirloom models), and the data can close a type again (`heirloomOpen`). Flameblade and the Soul Reaper live on as legacy skins (§8).
- [Built] **XP from fighting time.** A fighting card in the loadout gains XP for every second it fights (not while knocked out) plus a bonus per kill, so a card stuck at a wall still levels. The per-second rate grows with the dungeon tier like the kill bonus; the special dungeon pays the tier 1 rate. It is derived from fight time, so online and offline give the same result. Production cards keep their XP per gem harvested. Rates live in `cardRules.json`.
- [Default · in game] **Card XP curve** (Claude, balance run 2026-11-11). A level costs 60 × 1.12^(level − 1) XP (`cardRules.json` `xpCurve`; it was 10), so a Wood card takes about ten minutes of the first dungeon to reach Lv 20 instead of three.
- [Built] **Level caps by tier only:** 20 / 40 / 60 / 80 / 100 / 120 / 140 for Wood, Bronze, Silver, Gold, Prismatic, Mythic/Void and Heirloom (`cardRules.json`). Stars no longer raise the cap. A saved card above its cap keeps its level up to the cap.
- [Built] **Small bump every level.** Each level adds a little to the card's power, support strength and gauge speed (`cardRules.json`).
- [Built] **Weapon skills** (user, 2026-11-11; settles the Moves proposal). Upgrading a weapon opens skills in two places: milestone levels open enhancement options on the card (Enhancements below), and tiers open that weapon type's hidden circle in the skill tree (§10).
- [Built] **Star bar** (user, 2026-11-11). Each duplicate fills the card's star bar, the fill is saved on the card, and what is left over carries to the next star. A star costs a number of copies set per rarity and tier (`cardRules.json` `starBar.needs`): a fraction of a copy at the low tiers, exactly one at the rarity's top tier (the same for all five stars of a tier). The bar can hold fractions, so one copy may buy several stars at a low tier. No star is free and a tier-up lands at ★1. Because stars cost fractions of a copy, the bar is shown as a percentage of the next star ("40% to ★2") with the exact copies in the tooltip.
- [Default · in game] The copy cost of a star per rarity and tier (Claude, balance run 2026-11-11; `cardRules.json` `starBar.needs`): one copy at the rarity's top tier, and below it a share that halves a tier for Uncommon and Rare (Uncommon ¼ at Wood; Rare ⅛, ¼) and starts lower for the rarer cards, so a card found late can catch up: Epic 1/32, 1/16, ⅛ from Wood to Silver; Legendary 1/64, 1/32, 1/16, ¼ from Wood to Gold; Mythic and Void 1/64, 1/32, 1/16, ⅛, ¼ from Wood to Prismatic, then one copy at Mythic or Void and at the Heirloom. A Common needs one copy a star at Wood, its only tier.
- [Built] **Star dust** (user, 2026-11-11). A rare material that pays for a star in place of a missing copy, more of it for higher rarities and tiers. It is rare on purpose, so pulling stays the main way to star a card. It comes from stage star levels from Gold up (§6) and from the forge (§4). Built: the resource, its price (`starBar.dust`, dust per whole copy by rarity and tier; the missing part of the star is paid, rounded up), the weapon panel's button (`starUpWithDust`) and both sources: stage star chests from Gold up and the forge.
- [Default · in game] Star dust amounts and prices (Claude, balance run 2026-11-11): stage chests give 2, 5 and 15 star dust at Gold, Prismatic and Mythic (×2 on Hard, ×4 on Nightmare; `combat.json`), the forge makes 1 from 20,000 Moonwillow and 20,000 Grotto gems for 3,600 work (`production.json`), and a copy costs 5 to 2,000 dust by rarity and tier (`cardRules.json` `starBar.dust`, unchanged). In the sim a player earns about 250 dust in 40 hours.
- [Default · in game] **Star dust survives an Ascension** (Claude, 2026-11-11, the orchestrator's call: it belongs to the collection, like the cards it stars). It is a material, but its resource is marked `keptOnAscend` in `resources.json`, so an Ascension skips it like Starlight and the crystals.
- [Built] **Star impact.** Base damage and health are multiplied by ×1.25, ×1.6, ×2, ×2.6 and ×3.5 at ★2 to ★6. The bonuses of supports and the main growth keep their smaller star step (`cardRules.json` `power`).
- [Built] **The tier's power step** (Claude's proposal in the balance run, confirmed by the user on 2026-11-11). Base damage and health (and a worker's power) step ×3.5 a tier: ×1, 3.5, 12.25, 43, 151, 529 and 1,852 from Wood to the Heirloom (`cardRules.json` `power.statTier`), so a tier-up that restarts a ★6 card at ★1 never makes it weaker (★6 is ×3.5 over ★1; `tests/balance.test.ts`). Before, the step was ×1.2 to ×1.6 and a tier-up cut a card's damage by more than half until it was starred again. Card effects (supports, main growth, gauge speed) keep the small step (`power.tier`: ×1, 1.2, 1.5, 2.25, 3.5, 5, 7), or the signature gauge would fire several times a hit.
- [Built] **Rarity matters** (user, 2026-11-10). A higher rarity must always be worth having. A fresh card of a higher rarity beats a fresh card of a lower one, and cards keep different stats by rarity (base damage and health, `cardRules.json`) and by weapon type. ## 6. Combat and dungeons

- [Differs] **Fight pace** (user, 2026-11-10). Bosses are auto-fought in parallel with everything else, with no combat input, and respawn so they can be farmed. Fights are short and both sides bleed: a loadout that matches the dungeon kills its boss in about 15 to 30 s, and one that is too weak falls in about 10 to 20 s. Bosses are no longer HP walls that cannot hurt you. Built in `dungeons.json` and checked for the first dungeon: a fresh game falls to the Root Warden before it kills it and wins once its cards have levelled and its first pulls are in (the first clear at about 12 min in the sim, 2026-11-11). Not yet held deeper in: a loadout that clears a dungeon keeps growing and soon kills its bosses in 1 to 2 s, because three dungeons cannot cover the power a run gains. Floors are built (Dungeon floors below), and the tiers, endless depths and the ladder retune (Scope 3, phase 9) are what keep fights in the 15 to 30 s band. HP shows as stacked bars with a ×N count of bars left; the current bar drains over the colour of the next.
- [Differs] **Floors pace** (user, 2026-11-10). On floors, a normal wave dies in a few seconds and a mini-boss in about 15 to 30 s. Built: a wave has a fifth of the HP a boss would have on its floor and a mini-boss three fifths (`combat.json` `floors`), so a loadout that takes the boss in 15 to 30 s takes a wave in 3 to 6 s. Not tuned yet: the shares are a first setting, and the ladder retune (Scope 3, phase 9) checks the band with the sim.
- [Built] **Knockout** lasts 10 s instead of 30 (Claude, 2026-11-10), so a lost fight costs little time and the next try comes quickly (`combat.json`).
- [Built] **Attack animation follows hit speed** (user, 2026-11-10). The attack animation plays over a share of the main card's hit interval (40%, clamped to 200 to 900 ms; `theme/attackSpeed.ts`), clamped to a readable range, so a dagger swings fast and a hammer swings slowly. Reduced motion stays as it is.
- [Built] **Enemies do not grow with Ascension** (user, 2026-11-11; drops "Harder each Ascension" of 2026-11-10). Harder enemies come from the difficulty tiers and the endless depths, which the player picks; an Ascension restarts the economy and leaves the enemies as they are (§9). The guard stays: each run must be faster overall than the one before, and the sim checks that every run reaches its first 5 milestones sooner than the previous run did (§14).
- [Built] **Dungeons.** Mossy Cellar (Root Warden, drops Moss Core), Ember Crypt (Cinder Lich, Cinder Core, a few Frost Cores and Frost Sigils) and Frostspire Vault (Glacier Colossus, Frost Core and Frost Sigils). Every kill drops Money; crystals come as a wage (§3) (`dungeons.json`).
- [Built] **Arena backgrounds** (user, 2026-11-10). Each dungeon gets its own arena background, named in `dungeons.json`; the art comes later.
- [Built] Until a dungeon's background art exists, every arena uses the same dark brick room with two torches, drawn in CSS.
- [Built] **Dungeon floors** (user, 2026-11-09). A dungeon is a stack of floors. ## 9. Prestige: Ascension

- [Built] **One layer, Ascension,** granting Starlight, a permanent prestige currency.
- [Built] **What Ascension means** (user, 2026-11-11). It restarts the economy and never the collection: tree and mine levels, Training, Money and materials start again and Starlight makes the next run faster, while cards, their stars and tiers, cosmetics, crystals, unlocked difficulty tiers and stage stars are never touched. Difficulty tiers and depths are how the game gets harder; Ascension is how the economy gets faster. Enemies do not grow with Ascension (§6).
- [Built] **Ascension resets** tree and mine levels, the training levels (§6), Money (back to the starting amount), gems, Cores and the other materials, the per-run shelf upgrades, and the floor each dungeon stands on, which restarts at half of its best floor (§6).
- [Built] An Ascension also resets the tool lines and the depth and age of mines and trees, and opens a worker slot (§4). It keeps the workers, the forge, star dust, stage stars and their chests, the wishlist, the skill tree's bought ranks and every card with its stars and tiers (one test lists all of it, `tests/ascensionKeeps.test.ts`).
- [Built] **Ascension keeps** cards (levels, ranks, loadouts), cosmetics, unlocked dungeons, the unlocked difficulty tiers and the best floor and depth of each, tree kinds and mine types, the crystals, Starlight, portal pity, stage kills, chests and overflow switches, the Glimmer Trial medal, gem mastery, the permanent shelf upgrades and lifetime Money earned.
- [Built] **Starlight shop.** Permanent levels: logging and mining output, damage, card health, crystals, slower price growth and the offline cap (`prestige.json`).
- [Built] **More to buy with Starlight** (user, 2026-11-11). The Starlight shop also sells the second worker slots (§4) and the autobuyers for tree and mine levels (§15), and each Ascension opens a ring of the skill tree (§10), so an Ascension unlocks something new and not only a bigger multiplier.
- [Default · in game] **Second slots and autobuyers in the shop** (Claude, 2026-11-11; `prestige.json`, placeholder prices). Second Hands has six levels, each giving the next tree or mine in order (trees, then mines) a second worker slot, and cannot be bought until the Ascensions have opened a first slot on every tree and mine; a second worker's output adds to the first's, and the second slots add to the slot count (twelve workers at most). Timber Steward and Vein Steward are one-level purchases that unlock the autobuyers (§15). A shop line that opens a rule has `grants` in place of `perLevel`.
- [Built] **Prestige cosmetics:** Gilded Plate at the first Ascension, Aurora Veil at the second, Gilded Filigree at the third.
- [Default · in game] Starlight = floor(((gems harvested this run × tier weight 1 / 10 / 100) / 2e10) ^ 0.4) and an Ascension needs at least 10 (`prestige.json`; the divisor was 3e6, balance run 2026-11-11), which puts the first Ascension at about 8 hours. Constellation Crystals gives +4% crystals a level (it was +10%). Ascension also resets the burst gauges, the boss being fought, the loadout's health and a running trial attempt. A repeated prestige cosmetic becomes a copy.

- [Built] **Skill tree** (user, 2026-11-11). The main balancing glue, in two layers: the account tree and the card enhancements (§5). It is laid out in rings: the inner ring is open from the start and each Ascension opens the next ring out. Skill points come from account levels, stage star levels (§6) and achievements. It supports respec, and every effect goes through the modifier pipeline (§14). It has eleven branches (Logging, Mining, Combat, Summoning / Luck, Collection, Automation / Offline, Workers, Forge, Elements, Dungeons and Ascension) of 15 skills each on one skeleton, the eleven weapon circles of ten skills, four rings, and skill points from account levels, stage star levels and achievements. How much of total power the tree gives was measured in the balance run (2026-11-11): about +85% to +130% damage from 4 hours on, beside Training's ×2 to ×5.

It switches its autobuyers on and holds them while it saves Money for a tier-up. After buying a level of the best economy line it takes up to 25 more of that line, and when those were cheap a mine or tree then takes as many levels as a 25th of what is left pays for, through the game's bulk buy (one Max at the bulk cap per line per look). The first Ascension is taken as soon as it pays the minimum, later ones when the gain at least matches all the Starlight earned and either the run's Starlight per hour has passed its peak or the gain is three times all the Starlight earned; the player finishes the fighting lead's upgrades first, saves a tier-up's Money only when it is the last thing missing, and holds an Ascension while a tier-up is three quarters funded. ## 15. Systems chosen for the beta, not built

_The user chose these on 2026-11-07 in claude.ai. The handoff to the repo never happened, so they were in no document and nothing was built. The systems are the user's choice; the details were filled in by Claude and are defaults._

- [Built] **Loadout presets.** Each dungeon remembers its own fighting loadout and switches to it when picked; production jobs get named presets.
- [Default · in game] Three presets per production job (name, Use, Save here, Clear on each production band). The dungeon's loadout is remembered when you leave it; a dungeon with nothing remembered keeps the current loadout; a remembered card that is gone or away leaves its slot empty; a loadout over the cost cap is flagged and not applied, never deleted. Workers have slots, not a cost cap (0.6.0), so a worker preset that needs more slots or places than are open is applied as far as it fits and flagged with how many did not fit; it stays saved as it was.
- [Built] **Bonds.** Specific pairs of cards in the same loadout unlock a small named bonus. An undiscovered bond shows as a silhouette in a Codex until first triggered; a pixel chain links the two cards on the table.
- [Default · in game] Oath of Dawn (Ember Squire + Dawnblade Regent: +2 burst fill per hit), Old Growth (Apprentice Feller + Elder Treant: harvest bursts +5 s), Deep Vein (Cave Digger + Geode Golem: +15% mining). A fighting pair is active while both are in the fighting loadout; a logging or mining pair while both work, at any tree or mine of their job (Claude, 2026-11-11). The bonus enters through the modifier pipeline (source `bond`) and a bond is discovered the first time it is active, recorded on the 1 s grid.
- [Built] **Expeditions.** Cards not in a loadout go on timed trips to places opened by clearing dungeons and bring back that area's materials, some gems and card XP, double for a matching element. They are plain timers outside the offline cap. A card on a trip cannot be equipped.
- [Default] Trips of 1, 4 or 8 h to Mossy Outskirts, Ember Catacombs and Frostspire Pass; one slot at the start, one more from the account tree and one from the Starlight shop; recalling early returns nothing. The places' elements are Nature, Fire and Crystal, the elements their dungeons' bosses resist (Claude, 2026-11-11). Rewards per hour of trip, doubled for a matching element: the dungeon's Core (1), 120 seconds of the place's gem output (Oak, Ironbark, Moonwillow gems at their current level) and a tenth of the card's current level in XP. The extra slots are the account tree's Grand Archive keystone and the Starlight shop's Travel Pack (20 Starlight). All numbers are placeholders for the balance run.
- [To build] **Ascension challenges.** After the first Ascension, a challenge is an Ascension run with a rule, completed by clearing a target under that rule, up to three times with harder targets, each completion giving a permanent reward. They appear as side portals around the Ascension gate and each completion is a sticker.
- [Default] Lone Wolf (no supports), Common Folk (Commons only), Bare Hands (no damage lines), Drought (production ×0.5), Glass Cannon (health ×0.25) and Single Plot (one plot and one slot); completing all six once unlocks Auto-Ascend.
- [Proposed] Bare Hands and Single Plot no longer fit the 2026-11-08 changes (no damage lines, no plots) and need replacing.
- [Built] **Autobuyers** in the Starlight shop, each with an on / off switch and a reserve per resource ("never spend below X%") so tier-up materials stay safe. Card management (stars, tiers, pulls) is never automated.
- [Built] The autobuyers are for tree levels and mine levels (user, 2026-11-11) and are part of the balance update.
- [Default · in game] **How the autobuyers work** (Claude, 2026-11-11). Each is bought once in the Starlight shop and has its own on / off switch; one reserve (0 to 100%) is shared. They run on the 1 s play-time grid, where card levels settle, so online play, offline progress and any split of time buy the same levels: a pass buys the cheapest affordable level, again and again, but never spends a resource below the reserve's share of what was held of it when the pass began (tree levels cost Money, mine levels their own ore). The switches sit under the Starlight lines on the Shop page.
- [Default] New achievements: Bond Found, First Expedition, Rock Bottom (reach the last floor) and Challenger (first challenge completion). Bond Found (15 Glimmer Dust) and First Expedition (25 Star Dust) are in the game; Rock Bottom belongs to the stage battles and Challenger to the Ascension challenges.
