# Plan: the table update (everything approved, one release)

User, 2026-11-11: everything approved in any chat ships together, as one release (0.7.0). This doc is one-use: the release PR into `main` deletes it.

## Scope

Done means all of these are in the game:

1. **Every `[To build]` and `[Differs]` rule in `docs/DESIGN.md`** on this branch is built and tagged `[Built]` (or `[Default · in game]`). That includes stage battles (farming and Challenge, auto-challenge), each enemy with its own HP, a boss that dies once, the first-person card duel with a team of 4, training paid in gems, summon scrolls, the Focus Portal, the reveal show, loadout presets, bonds, expeditions, Ascension challenges, the Legacy Gate and tier looks.
2. **The UI rework:** motion E ("dealt from the deck"), layout 1a ("one table, no pages"), the dungeon as the focus, the table of mockup 4a. Mockups: `design/options/ui-layouts/` in the main checkout (untracked). The full views come from the picker the user answers; until then no UI package starts.
3. **The resource art** of PR #143 (currency icons, tier 4 tree tops), merged into this branch.
4. **The itch asset packs** (enemies, bosses, coins, crystals, achievement badges, credits): its own approved plan, `itch-assets.md`, built on this branch once the user has copied the packs.

Nothing approved is "later". If a package finds an approved thing missing from this list, it tells the orchestrator.

## Rules for every package

1. Branch from `feat/table-update` in your own worktree; open a PR **into `feat/table-update`**, never `main`. Do not merge: the orchestrator merges, one PR at a time.
2. Touch only the files your package owns (below). If you need a change elsewhere, make the smallest one and say so in the PR.
3. **Save format 27 for the whole release.** Package 1 bumps it and writes `v26ToV27`. Nobody bumps again; later packages extend that migration.
4. New numbers are placeholders tagged `[Default]`; package 12 tunes them. Keep `npm run sim` running.
5. Docs in the same PR: `docs/PROJECT_OVERVIEW.md` for every `src/` change, and the tags of the rules you build in `docs/DESIGN.md` (rewrite rules in place, no amendment sections).
6. Logic stays out of the UI and is unit tested. Content lives in data files with schemas. Numbers use `break_eternity.js`. Results must not depend on how time is split into ticks.
7. Mechanics packages (1 to 6) add only plain working controls in today's layout; the UI packages replace the layout. Do not redesign screens in a mechanics package and do not change rules in a UI package.
8. Verify before reporting: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, and a screenshot for anything visible (not committed). CI must conclude green on the PR.
9. No release, no version bump, no tag, except package 13.
10. Do not delete this plan doc, except package 13.

## Interfaces

Written by package 1 (save format 27). Every piece below is saved, loaded, cloned and validated, and is **inert**: no rule reads it yet, so the game plays exactly as 0.6.0 (the sim prints the same tables). Types live in `src/game/state.ts`, the on-disk shape in `serializedStateSchema` (`src/game/save.ts`), the step in `v26ToV27` (`src/game/migrations.ts`), its tests in `tests/saveV27.test.ts` with a real 0.6.0 save, `tests/fixtures/saves/v26-0.6.0.save.txt`.

How to extend:

- **Nobody bumps the format.** If you change or add saved state, change the type, `serializedStateSchema`, `serializeState` / `deserializeState`, `cloneState` (or the clone helper) and `v26ToV27` together, and add a case to `tests/saveV27.test.ts`. Unknown ids are dropped on load (`deserializeTableUpdate` in `save.ts`), so a rule may trust every saved id.
- **Removing an old field** (`mode`, `loadoutDamage`, the crystals): drop it from the type and from `serializedStateSchema` (zod strips unknown keys on load), and say so in your PR.
- Everything kept through Ascension unless the line says otherwise: `ascend` spreads the state, so a field is kept until the owner resets it there.

### Card duel (package 7)

| State               | Shape                     | Meaning                                                                                                                                                                                                                                                                                                                                 | Owner |
| ------------------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| `combat.cardDamage` | `Record<cardId, Decimal>` | Damage each team card's own health has taken; missing = full health; at or above the card's max health it is knocked out. Only owned fighting cards are kept on load. Built by package 7 (`duel.ts`); `combat.loadoutDamage` is removed from the type and `serializedStateSchema` (zod strips it from old saves; `v26ToV27` unchanged). | 7     |

Built (package 7): **the team** is the fighting loadout in order, `cards.loadouts.fighting.main` then `supports[0..2]`, skipping empty, unowned and repeated slots (`teamCardIds`, `buildTeam` in `duel.ts`). A card's max health is its `cardHealth` with the team's `combat.health` modifiers shared in proportion, times its skill's health factor (own health, not equal shares); **knocked out** is being in `combat.cardsOut` (`string[]`, saved, default `[]`, added by `v26ToV27`, owned fighting cards only on load; a card whose max health rises while out stays out until the floor is won); the enemy hits the first standing guard, else the first standing card from the left; the fight is lost when every team card is out. Each card's hits and signature gauge sit on the play-time clock (hit k at k × its interval), so no timer is saved and `bursts.fighting` is no longer read by the fight. Roles and skills: `skills.json` (`Content.skills`, `skillById`, `cardSkill`). UI selectors: `teamView`, `duelEnemy`, `duelFightKey` with `emptyDuelLog` / `recordDuel` / `duelSheet` (`duelView.ts`); reports: `playerHits[].cardId`, `bossAttacks[].cardId`, `skills`, `cardKnockouts`.

### Table shell (package 8) — the contract for 9a to 9d

Built by package 8. The rules are UI_RULES §2 "The table" to "Live table"; the code is `src/renderer/src/table/` (the shell) and `src/renderer/src/views/<package>/` (one folder per view package). Nothing here is saved state.

**How a view plugs in.** Each package exports one `ViewPackage` from `views/<package>/index.ts`: `{ views: ViewDef[]; pieces?: TablePieceDef[] }` (types in `table/contract.ts`). `table/registry.ts` imports the four packages and fixes the dock order; a package never edits it.

- `ViewDef = { id, title, pile?, mount(host, ctx, api) }`. `id` is a `ViewId` (`table/viewIds.ts`: `dungeon`, `logging`, `mining`, `cards`, `summon`, `wardrobe`, `skills`, `achievements`, `shop`, `forge`, `upgrades`, `settings`). `pile` (dock views only) is `{ glyph: NavGlyph; hint?(ctx) => { text, ready? } | null }`; the hint is read about once a second, so keep it cheap. `mount` runs once at start: build the view into `host` (a `.shell-page` with a screen-reader `h1`, inside the view's scrolling `.vh-body`) and return a `ViewHandle`.
- `ViewHandle = { render(); opened?(from); closed?() }`. `render` runs every app tick (100 ms) while the view is open and once as it opens. `opened(from)` runs before the deal: move shared elements in here (`from` is the opener element or null). `closed()` runs after the exit animation.
- `ViewApi` (third argument of `mount`): `setTools(el | null)` puts an element at the right end of the title bar while the view is open (the buy toggle); `visible()` is true while the view is open and the window is visible.
- `TablePieceDef = { slot: 'centre' | 'left' | 'right'; view; label; mount(host, ctx) => { render() } }`: the dungeon window (9a, `centre`) and the wings (9b, `left` Logging, `right` Mining). `render` runs every tick while no view covers the table. The shell draws the piece's frame and its corner open button; a click anywhere on the piece that is not a `button`, `a`, form control, `[role=button|tab|switch]` or focusable element opens `view`.
- `TableContext` (`ctx`, one object for everything): `content`, `state()`, `apply(state)`, `director`, `coins` (where coins fly), `sound(id)`, `onTierUps(list)`, `cards` (the shared `CardsModel`), `applyTheme()`, `version`, `save.{exportText, replace, lastSavedAt}`, `open(id)`, `close()`, `current()`. Need something new from the app? Ask package 8 / the orchestrator; do not edit `app.ts`.
- Openers carry `data-open="<view id>"` (piles and the pieces' open buttons) for scripts; `scripts/shoot-table.mjs` shoots the table and eight views at 1280 × 720, 100% and 150%.

**Motion E** (`table/motion.css` tokens on `:root`, helpers in `table/motion.ts`): `--deal-ease` `cubic-bezier(0.22, 1, 0.36, 1)`, `--deal-exit-ease` `cubic-bezier(0.4, 0, 1, 1)`, `--deal-dur` 440 ms, `--deal-step` 90 ms (each later gap 10 ms shorter), `--deal-step-min` 40 ms, `--deal-max` 7, `--deal-scale` 0.92, `--deal-reach` 0.6, `--deal-exit-dur` 220 ms, `--deal-fade` 180 ms, `--deal-fade-reduced` 120 ms. Helpers: `dealIn(items, { from?: DOMRect; offset?; delay? })`, `dealOut(el, to)`, `fadeIn(el)`, `stopMotion(el)`, `reducedMotion()`, `dealTokens()`. The host already deals every view on open: the title bar, then the elements the view marks `data-deal` (else the page's top-level blocks), so a view only adds `data-deal` to its main blocks in reading order. Use `dealIn` inside a view only for a first-time moment (a reveal, a new card arriving), never for tab switches or lists opened many times. Animate transform and opacity only; everything stays clickable while it moves; every helper already honours reduced motion (Windows and Settings).

**Shared CSS a view may use (never redefine):** `px-panel`, `px-panel--raised`, `px-well`, `px-tile`, `px-btn` with `--gold` / `--dark` / `--quiet`, `px-display` (18 px and up only), `frame` / `frame__title`, `sr-only`, `bi-num`; tokens `--fs`, `--fs-sm`, `--px-*`, `--bi-chrome-*`, `--bi-frame-*`, `--bi-table-*`, `--dpr` (whole pixel scales: `ui/pixelScale.css`, `fitCard`), `--deal-*`, `--header-h` (64 px), `--view-bar-h` (56 px). Prefix a view's own classes with its folder (`dv-`, `gv-`/`gw-`, `cv-`, `mv-`) or keep the page's existing prefix.
